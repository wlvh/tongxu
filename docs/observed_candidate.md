# 已有远端 PR 与准确私有候选的关联

程序自产的私有集成候选已有 H/B/T/目标分支和原成员材料。远端 PR 由具有原发布责任的执行者建立后，使用本入口核对该 PR，再把实际观察交给原接收者。发布分支、生成私有对象、观察远端、测试、接收和用户接受分别记录。

先按现有 W1/W2 入口为**这个新 PR**采集和验证，导入同一队列。旧成员的验证不能代替它自己的验证。`observe-candidate` 使用导入时的准确 packet/fingerprint；不重新测试，不产生模型输入，也不创建 PR、推送分支或改变目标。

```text
node dist/src/integration-cli.js observe-candidate --store ABS_QUEUE --request ABS_JSON
```

请求使用 `schemaVersion: 1`、`kind: "tongxu-observed-integration-candidate"`，其余字段：

| 字段 | 含义 |
|---|---|
| integration | 原私有集成 id |
| item / packet / fingerprint | 新 PR 自己的原 W1/W2 导入引用 |
| source | 本次关联的依据；只是来源文字，不授予权限 |
| repositoryId | 固定 GitHub 仓库数字身份 |
| ghExecutable / ghSha256 | 现有 gh 的规范绝对路径和准确可执行文件摘要 |

H/B/T/PR/target 和原 S/r 从队列原件读取。程序仅执行允许的 GET：target ref、PR、仓库、再次 PR、再次 target ref。核对仓库身份、同仓库 head、开放 PR、准确 H 与真实 target B，以及前后关键字段一致。GitHub 的 `base.sha` 原文保留；真实 B 以实际 target ref 为准。观察有时间边界，不能证明期间所有远端状态原子不变，更不保证观察后永远当前。

实际请求、输入、HTTP 原字节、进程/退出记录和可执行文件摘要保存在队列旁的私有观察目录；成功捕获也进入原内容寻址证据和集成关联材料。独立接收入口收到原集成原因、失败前缀、完整 diff、原 W1/W2 与这份远端观察。关联本身不授权接收，也不代表接收者已实际消费。

旧本地关联可以补入远端观察，形成新 packet 并保留前一个关联摘要；旧判断不复制为新材料的判断。当前目标仍被活动或未知操作占用时，不改 packet。相同请求再次执行只进行新的 GET 核对，保留原关联与完整历史观察；不重复关联、W2 或模型任务。已知新的失败/未知读取会阻止新接收或合入投入；准确原件和新的实际观察恢复后，可沿原请求继续。旧消费者的 SQLite 执行门同样保留这一拒绝。

本入口保存的是**配置的可执行文件实际执行结果**。把自编程序命名为 gh，不会因此成为官方 GitHub 证据；测试中的本地 gh 协议夹具明确另列。官方 gh 真实读取、夹具控制路径、实际 W2 和实际模型运行各自报告，不用一个 PASS 或 `true` 字段互相替代。

独立169复核发现 OC-F01：较早开始的读取，最后一个GET晚返回，会用较晚完成时间覆盖期间已确认的PR关闭。原反例保留。修补把读取开始时的原队列观察版本纳入捕获绑定；期间发生任何新观察，旧成功和旧失败均不得改变新状态。单纯比较完成时刻不能提供这个保证。过期尝试的原HTTP和拒绝记录保存在自己的目录；沿原请求重新明确读取后可以继续。
