# 运行环境：最低要求与实际能力

同序要求 **Node.js 24.0.0 或更新版本**，不限定补丁版、大版本上限、安装路径或可执行文件摘要。使用的 `node:sqlite` 数据库事务属性 `DatabaseSync.isTransaction` 从 [Node 24.0.0](https://github.com/nodejs/node/blob/v24.0.0/doc/api/sqlite.md#databaseistransaction) 提供；启动时实际验证内存数据库的严格表、读写与事务回滚能力。缺少必要能力时说明具体缺项，不能通过改版本字符串放行。

正常 Mac 启动器由 `renderWorkbenchLauncher(runtimePath)` 生成。每次启动按PATH顺序逐一查找可用的Node，再检查常见安装入口和本机已有工具运行环境；不会复制一个私有Node作为应用依赖，也不要求恢复某个旧二进制。检查和应用启动在同一个Node进程内完成，不在预检后再次执行可能已改指的入口；应用开始加载后失败不会再试另一个Node。可选 `TONGXU_NODE` 只指定操作者选择的入口，仍只核最低版本和必要能力；该显式入口不可用时不偷偷换成别的程序。这个环境变量无需按版本更新。

`CURRENT_WORKBENCH.json` 的旧 `nodeVersion` 字段继续保留，含义是当时构建环境的观察值。实际运行记录分别写入本次 Node 版本、路径、最低要求和历史构建版本。升级 Node 不需要改写原清单；清单中的源码、构建文件和配置摘要仍核对，以防运行未经选择的产品代码或配置。

启动器只用本次私有临时目录中的阶段标记区分“候选程序尚未进入应用引导”与“应用可能已加载”。坏的PATH包装脚本可继续查找后面的Node；应用开始加载后的任何结果都结束本次选择，不会再次启动另一个Node。标记正常退出时清理，不保存为未来准入规则，也不是新的任务或操作账本。

## 外部依赖统一规则

所有外部依赖都按最低版本及实际所需能力使用，不设最高版本、发布版本名单、长期二进制摘要或固定安装目录要求。最低版本不是“未来所有版本都已验证”的承诺：若新版删除必要接口，修补使用方式并补测，不能要求恢复旧版本或只改版本字符串。历史版本、协议格式和当次执行摘要是证据，不能变成下一次运行的版本门槛。

| 依赖 | 当前要求 | 升级与原结果 |
| --- | --- | --- |
| Node.js | 最低24.0.0，实际SQLite事务能力 | 正常启动动态查找；构建时版本只作记录；已结束组合续做不比较旧Node身份 |
| TypeScript | 构建工具，最低5.9.3，无大版本上限 | 显式声明Node类型；运行时不再使用编译器内部语法树接口，当前TypeScript7可构建 |
| Node类型声明 | 最低24.19.2，构建依赖 | 不限定大版本；实际类型检查决定构建是否成立 |
| Acorn | 运行时JavaScript解析器，最低8.15.0 | 只解析不执行候选；受限表达式规则仍由同序自己的允许项决定，新语法不会自动获得执行权限 |
| Codex／Claude CLI | 当前程序的必要方法、参数、权限和完整回执 | 无发布版本名单；接受稳定符号链接，记录实际程序；旧日志格式用于解释旧字节，不要求旧CLI仍安装 |
| GitHub CLI | 当前`gh`标识及所需`api`选项 | 旧配置摘要只作来源；Homebrew旧版本路径沿同公式稳定入口解析；本次发送固定实际选择 |
| Docker客户端及引擎 | 本地Unix socket，实际信息/检查/创建/停止/日志命令和隔离能力 | 新准备核当前客户端；恢复可用升级后的客户端，只核原引擎、容器、原件及结束状态，不新建任务 |
| Docker镜像及容器工具 | 已有本地镜像、Linux、非root、默认过滤、零新增能力、必要Node/Git等工具 | 可配置稳定本地名称或标签；每次准备解析实际镜像ID，本次创建与检查使用该ID；下一次可解析新ID。旧摘要配置仍可读，不强迫新配置用摘要 |
| 专用发布／资源提供程序 | 操作者配置的稳定入口、原协议、实际账户、仓库、目标和能力 | 不再用旧程序摘要挡升级；一次能力核查到发送保持同一实际程序。升级后重新核查，原未知请求仍先回读、不重发 |
| Git／npm／bubblewrap及系统工具 | 实际使用的命令、格式和平台能力 | 不设发布版本名单；缺工具/隔离能力只阻止依赖它的动作，不关闭隔离来放行 |
| GitHub REST服务 | 原允许端点与返回字段检查 | 新请求不硬编码API日期，使用服务器当前默认；响应原始头和正文保留。历史带日期请求仍按原件读回 |

`package.json`只声明最低依赖范围。新安装用`npm install --ignore-scripts --package-lock=false`，不使用仓库锁文件强制安装旧版本；`.npmrc`关闭生成锁文件和安装脚本。已安装且满足条件的依赖可以继续使用，操作者可正常`npm update`，同序不后台更新软件。最低版本矩阵里的精确安装仅用于测试，不是产品配置。历史提交里的锁文件保留在Git历史和原包中。

稳定入口可由操作者的符号链接或安装器提供。对已登记的Homebrew版本目录，只沿同一公式的`opt`入口查找；不全盘搜索“最新文件”，不从报告里接受新路径，也不换账号或凭据。其他软件的任意安装目录消失且没有稳定入口时，报告入口不存在；这是没有可执行程序，不是要求安装同一版本。CLI自动更新抑制变量只作用于当次受控子进程，防止它在核能力与发送之间自行替换，不修改用户安装设置。

GitHub未指定日期目前仍采用服务器默认的旧日期，并会随服务淘汰规则变更，不能把省略请求头说成已使用最新API。参见[GitHub版本规则](https://docs.github.com/en/rest/about-the-rest-api/api-versions)。实际字段、账户、权限和结果核对继续生效；未来不兼容响应保留原件并报告具体缺项，不自动重试写入。

## 单次执行和历史证据

一次已经开始的执行固定实际程序、输入、候选、工具边界和原件；在发送边界或进程结束后发现程序变化会拒绝把结果当作已验证成功。跨次升级不是竞争写入、换人、重发或扩大权限的依据。文件前后检查不是对同权限恶意宿主的原子执行证明。

新运行可使用升级后的依赖；历史完成结果读取不执行今天的提供程序，不要求旧二进制仍存在。未知操作继续核原日志、实际进程和副作用；不能靠更新依赖、换目录、删除原件或改ID绕过。产品源码、构建及任务配置的完整性仍核对，依赖升级不等于切换未经选择的产品候选。

## 验证范围

针对性回归覆盖兼容升级、稳定入口、旧版本目录删除、能力缺失、提供程序在核查到发送之间变化、Docker镜像别名解析和新客户端恢复、原未知不重发、表达式解析拒绝反例，以及正常启动和历史全文读取。真实依赖安装/构建、实际官方只读接口、协议模拟测试、真实模型运行分别记录。Docker协议模拟不能代替真实隔离验证；未重新实跑的旧平台证据按影响范围保留。

此规则替代旧实施文档中把外部程序摘要、固定安装目录或Docker镜像摘要作为长期准入条件的条款；原协议格式、历史事实、权限和隔离要求保持。
