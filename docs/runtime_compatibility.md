# 运行环境：最低要求与实际能力

同序要求 **Node.js 24.0.0 或更新版本**，不限定补丁版、大版本上限、安装路径或可执行文件摘要。使用的 `node:sqlite` 数据库事务属性 `DatabaseSync.isTransaction` 从 [Node 24.0.0](https://github.com/nodejs/node/blob/v24.0.0/doc/api/sqlite.md#databaseistransaction) 提供；启动时实际验证内存数据库的严格表、读写与事务回滚能力。缺少必要能力时说明具体缺项，不能通过改版本字符串放行。

正常 Mac 启动器由 `renderWorkbenchLauncher(runtimePath)` 生成。每次启动按PATH顺序逐一查找可用的Node，再检查常见安装入口和本机已有工具运行环境；不会复制一个私有Node作为应用依赖，也不要求恢复某个旧二进制。检查和应用启动在同一个Node进程内完成，不在预检后再次执行可能已改指的入口；应用开始加载后失败不会再试另一个Node。可选 `TONGXU_NODE` 只指定操作者选择的入口，仍只核最低版本和必要能力；该显式入口不可用时不偷偷换成别的程序。这个环境变量无需按版本更新。

`CURRENT_WORKBENCH.json` 的旧 `nodeVersion` 字段继续保留，含义是当时构建环境的观察值。实际运行记录分别写入本次 Node 版本、路径、最低要求和历史构建版本。升级 Node 不需要改写原清单；清单中的源码、构建文件和配置摘要仍核对，以防运行未经选择的产品代码或配置。

启动器只用本次私有临时目录中的阶段标记区分“候选程序尚未进入应用引导”与“应用可能已加载”。坏的PATH包装脚本可继续查找后面的Node；应用开始加载后的任何结果都结束本次选择，不会再次启动另一个Node。标记正常退出时清理，不保存为未来准入规则，也不是新的任务或操作账本。

## 同类入口检查

| 入口 | 新运行的准入 | 原件与进行中操作 |
| --- | --- | --- |
| Node 启动器 | 最低24.0.0，实际SQLite事务能力；无版本名单或长期二进制摘要 | 保留当时构建环境，记录本次运行环境；源码/构建/配置完整性检查不变 |
| 已结束的组合任务续做 | 允许兼容Node升级、重装或换路径 | 继续核相同产品执行代码、原控制者/子进程结束、原请求、已完成步骤和工作区；新接续记录实际Node，不重发已完成步骤 |
| Codex／Claude CLI | 沿原能力检查：当前程序、所需协议、实际权限、回执及完整结果；不设发布版本名单 | 原始输入、会话和单次执行身份保留；旧日志协议标签用于解释旧字节，不要求安装旧CLI |
| GitHub CLI | 已配置程序可正常升级，摘要变化时核实际`gh --version`标识及`api --help`所需选项；支持稳定的符号链接入口 | 一次读取或发布捕获固定实际选择；执行前再次核对，进行中换程序拒绝。旧配置摘要作为来源保留；历史POST读回不执行当前gh或重发 |
| Git／Docker／bubblewrap | 原实现没有精确发布版本白名单；仍需实际命令、平台和隔离能力 | Docker镜像/端点及单次容器身份属于那次验证环境；不把不同镜像的结果当作同一份证据 |
| 专用发布／资源提供程序 | 属于明确配置的外部执行代码，不等同于通用官方CLI | 其授权材料、接口、执行身份仍须匹配；本改动没有授予新提供程序权限 |

GitHub读取/发布仍只使用原允许的端点、账户、仓库和当前候选。调用前及进程结束后核对本次程序身份；结果返回前发现变化会保留原件并拒绝验证，可能已发出的POST只允许核对原结果，不能自动重发。本人来源仍检查实际执行者、作者、最后编辑者和准确批准内容；程序升级不等于本人批准或权限扩大。若原配置写死了后来被删除的安装目录，需要改为现有稳定入口，不能根据报告文字或猜测路径接管另一个程序。文件前后检查不是对同权限恶意宿主的原子执行证明，不声称能阻止在检查间隙替换后又恢复文件。

## 验证范围

回归覆盖：历史构建版本与当前Node不同、Node程序内容/路径改变、最低版本与更高版本、缺少SQLite能力、错误显式入口、应用文件或配置改变、原组合结束后续做和活跃/未知拒绝，以及gh升级后的原捕获回读、错误能力和发送边界变化拒绝。用于测试的其他Node版本只是测试工具，不是交付安装的固定依赖。

历史版本/失败/原始报告不改写。测试夹具不代表真实模型调用、真实本人身份或产品接受。本条替代旧启动说明中把Node版本及摘要长期绑定为运行条件的部分；其余有效权限边界保持。
