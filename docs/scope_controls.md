# 原范围的直接停止、恢复与操作诊断

接续 Issue #9／#6／#8 的人控制部分，固定代码前置为 Draft #43 `5c6ed091180ac6ed9f702aa4ac48b8fb2d99f47e`。新分支 `feat/w7-scope-controls`，真实 target `feat/w7-task-controls`。前置的真实秘书联系链按实际执行版本 aa11 单独保留，不把新守卫的隔离验证改写成原生重跑。原全部52场景继续保留。

SC01 将原后端已有的三类停止／恢复接入显式启用的本机控制页面：新增实施、某范围新增投入、新合并。启动配置固定允许选择的范围和控制类型；浏览器不能提交任意 scope、队列路径、权限、命令或执行角色。页面明确显示影响的是该范围的相关任务，不误称只影响当前卡片。

SC02 复用原 controls/events 和现有消费者。准确范围／版本、当前修订核对和状态变更在原事务中完成；重复请求、丢回执或旧页面不能覆盖较新控制。每次记录请求来源、原修订与生效修订，状态改变不抹去原操作或报告。停止不被解释为杀进程、退款、回滚或抹去已经送达的任务。

SC03 保留本机影子控制与已验证 Owner 决定的区别。页面临时访问标识不是本人签名；本机入口不能打开已验证本人停止、代签目标采用或制造额外委托。恢复新增投入后，原授权、费用、资源、候选和写入责任仍各自检查。真实独立身份／Owner采用的装配继续是外部前置，不阻止软件、配置准备和隔离验证。

SC04 秘书查询与按钮显示同一原控制状态、准确来源和修订；秘书没有直接签署／恢复 Owner 边界的工具，文本建议不执行。人不依赖秘书在线即可操作已配置本机入口，原任务之间的通信和结果回读也不依赖秘书。缺少真实来源时显示具体等待，不改 false 字段伪装批准。

SC05 补前置真实核查发现的诊断缺口：联系程序在准备、权限检查或执行器阶段返回的失败／等待原因存入原任务记录，页面和秘书都可回读。控制器返回事实、消息是否送达、完整模型结果和资源未知分开；不能用一条控制器错误覆盖原成功结果或断言未发送。原始错误与恢复历史保留，不另造任务账本。

SC06 用实际进程和明确隔离夹具验证停止后零新派发、恢复后原授权路径正常继续、已发未知保留、并发／重复／旧修订、已验证 Owner停止不能被本机入口解除、秘书离线控制、错误持久回读与实际页面。必要独立复核后再按原费用和真实前置决定有界原生验证，不为每个故障烧模型额度。此项是原控制链接通，不声称目标／组织／成果／复盘五类入口及X1/X2已经全部完成。

## 配置和状态

原格式1联系目录保持不变；范围控制须显式使用 `tongxu-task-controls` 格式2。格式2包含原 `contacts` 和新增 `scopeControls`，两者可以有一个为空。范围条目分别固定 `id`、`title`、工作台选择源的 `source`、该源当前 `context.scope` 规范化 JSON 的 `scopeSha256`，以及一种 `control`（`implementation`、`investment` 或 `merge`）。一个原范围／控制类型不重复配置。只读工作台仍不接收任何写入请求。

按钮只发送目标状态和它刚读到的控制修订。后端用固定目录生成稳定请求标识；重复旧请求返回原回执，并另附当前控制，不能把旧状态再次写回去。同一状态不会改写已存在的来源或增加控制修订。若已有经过核实的本人范围采用，新版本会使旧配置失效；已验证的本人停止仍由原 SQL 守卫保护，本机入口无法打开它。

这些操作沿用原 `control` 的本机语义：它们让原消息、实施和合并消费者检查停止状态，恢复不新增权限，也不证明远端执行已停止。本机临时访问标识只开放启动配置中的操作；秘书只读取同源状态，没有对应控制写工具。

## 可恢复的入口诊断

联系入口的返回观察追加到原 TaskInbox 的 events/blobs，保留准确请求摘要、目录摘要、期望材料、阶段、已知 run 和错误原件摘要。普通页面／秘书查询只读取原因代码和摘要，不带错误栈、私有路径或原请求全文。相同的连续观察可复用，历史有明确上限；这些记录不用于累计模型调用或授予权限。

失败可能发生在待办登记之前，也可能在实际执行之后。记录统一标明 `controller_return_not_dispatch_proof`；发送状态仍由原 MessageRecords 的捕获和回执决定。未知的新请求数保持 null。一个后续入口错误不会抹去先前已完成报告，也不会把已送达但未完成的运行改成“未发送”。日志写入本身失败会明确返回诊断未保存，不重发模型来补日志。

每次等待调用持有自己的执行引用；后一次零输入重读不能覆盖前一次的返回。若诊断追加失败，HTTP／直接调用明确给出未保存状态和原因；当前服务查询与页面另显临时提示，不伪造持久化记录，也不替换原历史。重启后该未保存提示不保证保留，原历史继续按原样读取。
