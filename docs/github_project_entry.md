# GitHub 项目启动入口

正常启动同序后，先检查本机现有GitHub身份，再显示该身份可访问的仓库。这里的项目指GitHub仓库，不是GitHub Projects看板。所选仓库决定整个工作台：Issues、PR、任务、完整报告、协作、目标与控制，以及秘书都围绕这个项目。Issues和PR可筛选、分页和阅读完整正文。

项目列表每页50个，条目每页30个，界面明确显示已加载数量和后续页。每个页面继续使用自己上次收到的翻页位置，其他页面刷新不会替换它；位置必须属于相同账号、项目、列表类型和筛选。每个后续页在本次运行内最多保留64个已返回位置，过期或不匹配时明确要求重新读取，不悄悄换用其他位置。各页仍是GitHub当次查询，不宣称多页构成单一时间点的冻结快照。项目筛选只检索已加载列表，不声称搜索了尚未加载的全部仓库。Issues与PR使用各自的连接读取，分页位置来自GitHub返回的游标；空页和后续页分别展示。

## 使用与配置

已安装的本机入口仍为桌面tongxu目录中的START_WORKBENCH.command。页面首先选择项目，随后左侧各项都使用同一个项目；当前仓库名持续显示。项目归属读取原队列与原任务中的repository，历史记录不复制、不换绑。只有进入该项目的任务或控制页面，才初始化该项目的原控制与已配置补查，其他项目的失效模板不会阻止它。没有同序任务的仓库显示真实空状态，可继续查看它的Issues和PR；不拿另一项目或测试样例填充。

安装配置沿用WorkbenchPlan，只增加`githubProjects: true`。未关联本机任务的项目可以使用空`sources`，不需要手工登记仓库、操作编号或计划JSON；项目选择直接来自当前身份实际读取的仓库列表。原来源配置和原问答文件不改写。每次冷启动重新核连接并选择项目；浏览器内切换不自动创建执行任务，也不取消此前已发送的执行；再次选择原项目可读取原结果。现有任务和秘书仍使用原来源与权限配置，选择一个仓库不等于导入所有Issue为执行任务。

GitHub读取沿用本机gh认证。查找PATH中的gh及现有常见稳定入口；可选TONGXU_GH仅为操作者明确指定入口。按程序实际能力准入，没有固定CLI发布版本或新token。未登录、网络失败、权限不足、频率限制和不完整响应均显示为具体失败及重试，不能替换成空成功列表。页面不收集密钥。

## 读取边界与运行寿命

- 本机访问仍要求127.0.0.1、正确Host/Origin和本次随机访问钥匙。
- 本机新接口只接受GET。远端使用固定GraphQL只读query（HTTP POST传输），在同一次认证请求里取得viewer身份和相应仓库/条目；没有mutation，不接受页面传来的查询文本、任意URL或shell。
- 仓库选择绑定GitHub数值ID和当前用户ID。切换账户使旧选择失效，每份项目数据与身份来自同一次查询，避免分别读取身份时账号在中间变化；返回较迟的旧项目请求不能覆盖或撤销新选择。
- 列表和详情直接展示GitHub读取结果，正文按文本处理，不执行HTML或报告指令。详情链接由已核仓库名、类型和编号构造。
- 选择和浏览不克隆、不调用模型、不导入候选或授予新权限。用户在项目内明确发起已有任务动作时，继续由原执行器核查输入、工具、费用、写权和重复记录。
- 所有原任务读取与操作请求携带当前账号和仓库ID；服务器对每次原接口请求通过固定query重新核对当前GitHub身份和仓库可访问性，再按原队列/任务归属限制来源与控制；写操作解析输入后再核一次。登录切换、权限撤销或网络失败时明确拒绝本次请求，保留此前已读页面和原件，不将缓存当作当次认证。猜测另一项目的报告地址、秘书source或动作ID不能访问或执行它。页面不传目录、模板或新权限。每个页面的项目上下文独立，不以服务端全局“当前项目”覆盖其他页。
- 切换项目清除旧任务选择与弹窗；迟到的原任务状态、报告或操作回复不得覆盖新项目。未核清归属的本机来源明确计数，不冒充属于当前项目。原队列不可读时已知项目保持缺项，相关写入等待核查。首次归属未知时不缓存不完整控制器，也不启动其补查或动作；同一来源恢复后刷新即可接续。已在运行的原控制器保持身份，不删除或复制。成功和失败提示同样绑定动作发起时的页面，切走再切回也不会补显示旧提示。
- 旧项目响应不会重画用户正在筛选的项目列表；当前列表更新保留筛选文字、焦点和选区。启动信息失败后的刷新重新读取入口，不自动改走历史工作台。
- 关闭本机进程取消未完成的GitHub读取，包括CLI版本与能力探测子进程，不启动后台刷新。每次打开浏览器入口会重新核GitHub；旧访问钥匙不能用于下一次启动。

## 验证

针对性测试覆盖分页、Issues/PR区分、完整正文、错误身份、任意路径拒绝、账号切换、读取中身份改变、权限/频率/格式失败、取消、历史数据延迟加载，以及前端迟到响应与部分失败。新增针对性验证覆盖两个项目各自的任务、全文和秘书、无任务项目、跨项目读取/操作拒绝、账号变化、迟到结果、重复与冷重开。实际试用另行记录登录身份下的项目、Issues/PR、原任务与全文；测试程序数据不作为真实GitHub或真实模型证据。原工作台和秘书读取回归按影响范围复用。

官方接口依据：[GraphQL查询与viewer](https://docs.github.com/en/graphql/reference/queries)、[可访问仓库](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user)、[仓库Issues](https://docs.github.com/en/rest/issues/issues#list-repository-issues)、[仓库PR](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)。
