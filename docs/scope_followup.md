# 已采用新目标后的原负责人接续

本增量处理原 #9 正常使用流程中的具体断点：目标表单已经记录新的 S，旧任务定义仍准确绑定旧 S。它保持旧定义、旧 packet、报告和工作区，在同一原队列中创建明确关联的后续任务，沿用原 A 的逻辑职责配置；不把新的原生会话称为恢复旧会话。

## 准备与执行

“目标与边界”入口在检测到当前采用与最近相关任务的范围不同时，允许填写本次工作和验收说明。原材料已变化时，可以显式重新观察原已选文件，再保留草稿并采用新观察；旧材料和报告继续保留。后台核准确父任务、当前材料与当前已采用范围；重新读取原本人来源；核相关任务链的原请求均已返回、撤回或明确关闭，且原操作已结束。活跃、未知和仍排队的原请求继续阻止竞争接续。

准备只读取原已声明路径，保持 workspace、base、target、路径范围和原参与者的工具/程序/限制。它生成原 TaskInbox 请求、固定输入和控制文件，并准备准确的 coordinate 动作提案。没有领取模型额度、没有发送模型、没有获得业务写权或生产接受。原工作区的未提交文件与暂存区保持；读取仍沿用原“所选路径、未检查整个工作区”的边界。

后续输入保留新采用的完整目标边界、旧任务定义、原请求引用以及最近原运行的完整角色输入和回复。原补充/中断记录也随原结果保留。前一后续请求仅准备后撤回时，下一次接续继承仍保存的最近实际原报告，不把零输入当完成。不裁剪报告冒充全文；材料超过既有上限则明确拒绝准备。

页面直接核对准备提案的原本人确认来源，也可选已有且范围匹配的协调委托。执行仍由原权限、资源、消息、TaskControls 和原生执行器检查。采用目标不自动等于动作已授权。旧用量证明的观察时间不被修改；当前执行事实不适用时，发送前仍拒绝。未知结果先查原运行，已完成结果重放不请求新模型。

准备时的结束观察不当作永久执行锁。原 TaskInbox 接收新请求、首次装配，以及原消息执行器登记运行和发送时，都在原队列事务中复核其余关联任务。已经准备的后续工作会阻止旧任务另起竞争请求；原相关执行后来活跃或未知时，已准备任务也不能发送。确认未发送的请求可显式撤回，再按原记录继续；不通过删锁或换目录绕过。

原 A 的已验证控制配置具有 interrupt 时，后续请求只保留准确中断选项，并绑定新的消息；旧范围的补充文字不复制成新目标的指令。页面中断只作用于本入口实际拥有的 thread/session/turn。中断原件保留，明确结束该请求后才可准备下一次接续。

## 同一页面与秘书

后续工作在原目标入口中显示准备、授权、原执行状态、准确新会话和完整报告；后台生成内部 ID、摘要和控制文件，不要求用户手写 JSON 或复制角色报告。同一个任务ID在不同所选队列里，控制器、授权选择和报告均按原队列区分。所选父任务之外的对象不能由 HTTP 参数引入，模型报告不能提供新的路径、工具或权限。

秘书的工作台查询读取相同原队列的后续工作关系与持久状态，控制器活动仍为未观测。显式 `scopeFollowupReports: true` 才增加完整后续报告工具；它仅读取已选任务的明确后续任务，不能准备、采用、开始、取消或中断。未启用该能力的原工具集合保持，旧完成捕获继续按原输入查回。

## 验证与保留边界

作者已用真实本地 Git、SQLite、HTTP 和明确进程/来源夹具验证：带暂存/未提交内容的准备及实际执行、旧任务与原件保留、重复零发送、未授权拒绝、排队/活跃/未知的阻塞、源变化拒绝、同页授权与完整报告、重开入口，以及 S2 未发送撤回后继续 S3。原生中断后按原记录明确关闭，随后新范围接续仍保留原职责和中断事实。秘书工具的实际捕获、全文和零重发已单独检查。

这些是开发验证，等待准确固定候选独立复核及浏览器完整流程证据；不是当前实际本人采用、额外付费、正式生产写入或全部52项验收。原目标、组合测试、接收、RETURN 和远端关联能力继续复用。后续仍按原 goal 完成正常入口装配、成果验证/评估和复盘基线等尚缺连接。
