## 当前入口与证据边界

`npm run member-repair -- run --plan /绝对路径/member-entry.json` 是单个操作入口。`prepare` 只固定输入；`reconcile-ended` 只在原执行已经结束并且原修复器核清现场时接续。入口固定原组合退回、成员项目请求、CLI 配置与原 operation；角色报告不能产生命令、权限或修改路径。成员使用自己的写入授权和资源，原父接收报告保持原身份，不制造成员自己的接收结论。

入口保存完整原件和生成的内部修复计划；原始选择文件随后被移走仍可读取本次完成结果。已完成执行在授权被撤销后仍可零新输入回读；未知或未结束执行不能用新 entry 标识绕过原计划。

新成员退回证据会令该成员旧接收结论失去当前适用性，并加入相关集成与交付成果的输入证据。旧报告、原 Owner 决定和准确候选均不改写；新证据不自动撤销用户授权，也不恢复已经停止的投入。当前队列格式显式升级到 20，保留原功能版本；首次升级要求队列空闲且没有尚未核清的发布意图。实际资源认领与发布意图都有数据库守卫，已打开的旧客户端也不能绕过本轮核对。

MR01–MR03 有实际 Git／受管文件修改／Docker 测试／独立角色协议的隔离夹具验证；这些模型是明确的测试脚本。1fe8 独立审核发现 IMR-F01（父来源变化后的资源认领）和 IMR-F02（预打开旧发布器仍写出旧 PASS）两项 P1；修补保留原反例，当前作者复验分别取得零 claim 和零 POST，新的独立结论仍须绑定修补后的准确提交。

## 修复后重新组合

`npm run member-repair -- recompose --plan /绝对路径/recompose.json` 消费已完成原修复的终态原件和独立采集的新成员 W1。新 W1 的 H 必须等于修复器实际产出的 H，repository／PR／B／target 必须仍属于原选中成员；程序不会修改旧 W1 的版本字段来伪装一次远端采集或发布。

程序从原队列还原其他成员的准确清单，在自己的私有 Git 目录只导入原选定对象与修复对象，实际执行重新组合的 W2，再形成新的最小集成候选。新接收材料包含原父报告全文、被修复的问题、实际修复和再审结果，以及新组合的准确成员列表；旧 PASS 不转移给新候选。新候选还必须通过自己的 W2、独立接收和原合入消费者。正常路径及导入后／关联后中断恢复均使用同一请求与原运行，重复完成入口不再运行 Git 或模型。

本入口当前采用既有未装配 Owner profile 的操作人测试路线。已装配 Owner profile 的队列会在新测试前明确拒绝借用成员 implement 授权；精确新组合 test 授权的装配仍是软件待补部分，不把它记作用户批准缺失。测试中的新成员／新集成 PR 身份明确是隔离夹具，Git、Docker、文件修改与消费是真实操作，模型仍为测试脚本。

尚未完成：MR05 真实 Agent 完整链、无代码修改的反证结论如何进入新鲜接收、受治理重新组合的精确测试授权和真实远端新候选发布接入；原 MI05 已结束的部分 Git 构造接续也仍单列。上述缺项保留在原 goal 中，当前子范围不声明完整 G05/G2 或全部 52 场景完成。
