# 官方 CLI 按实际能力接入

Codex CLI 和 Claude Code CLI 的版本号不作为新运行的准入白名单。用户配置现有官方程序的路径后，正常升级不要求逐次修改任务模板、版本字符串或长期文件摘要。原始版本、路径、摘要和协议记录继续用于追溯每次实际运行。

本规则来自用户在首版实际试用中确认的修正：官方 Codex 升级后，不应只因旧版本/摘要不匹配而阻断已支持任务。它替代旧实施说明中“新运行仅允许指定 CLI 版本”的要求，不改写当时的运行证据。

## 新运行检查什么

- Codex：取得当前 `--version`、help 和由该程序生成的 app-server 请求 schema；核本次需要的方法及参数，再沿原会话握手核实际认证、普通订阅用量、工具边界、只读/网络限制、准确线程和轮次。方法或关键参数缺失时报告具体能力缺项，不通过版本号推断支持。
- Claude：核当前 CLI 的必要选项，执行一次不含用户消息的 SDK 初始化，核实际版本一致、`dontAsk`、空命令集、idle、关闭 fast mode 及无待决权限请求。实际模型运行仍另核订阅路线、空工具/MCP、原输入回执、会话、完整结果和命令终态。初始化成功不是模型任务完成。
- 新消息/元数据读取使用配置的程序路径，记录这次实际选择的可执行文件。旧配置摘要作为安装历史保留，不充当永久版本锁。单次请求登记后的运行输入与原件仍不可改写。
- 新秘书问题由程序在原登记事务中装配当前运行身份，用户只填写问题。同一请求重入先读原记录；不会因 CLI 后来再次升级而重新发送或重绑旧问题。直接秘书入口也保存原计划和本次选择，保持同一恢复边界。

这不是取消检查。某项必要协议、权限或结果能力确实缺失时，只暂停对应操作；未知、部分回答、错误会话和矛盾终态仍不能放行。没有自动降级为任意shell、API计费、宽权限或其他执行器。

## 旧结果和会话

旧记录中的版本专属协议标签描述其原始字节结构，保留不变。新 Codex 捕获使用线程/轮次契约加实际观测的版本；新 Claude 捕获使用实际核验的流式命令契约。历史读回不要求旧 CLI 仍安装，也不运行新的模型。

会话恢复仍须核原执行已结束、原候选和输入完整、唯一写入责任以及实际恢复的线程/历史。当前 CLI 可以不同于创建旧会话的版本，但不能据此换会话、丢弃原输入或把新上下文称为原恢复。缺能力或未知原执行照常等待。

## 证据边界

官方 CLI 的 help/schema 和零输入初始化是能力观察；实际会话权限、输入消费和完整结果仍由执行捕获验证。显式测试程序只产生 fixture 证据，不能被称为官方模型调用或生产授权。版本可变化不意味着任意未知协议都自动兼容。

首版 `v0.1.0-trial.1` 与全部原始证据保留。本次实际环境观察为 Codex `0.163.0-alpha.11.2`、Claude `2.1.304`，这些是观察值而非新的支持名单。完整本机原件在本次 Issue9 试用记录中；原 T22/T26/T34/T52 及唯一 currentRemainder 的 F08-CLI-CAPABILITY 跟踪本增量。

官方依据：[Codex app-server 的版本对应 schema 导出](https://learn.chatgpt.com/docs/app-server#message-schema)、[Claude CLI 选项](https://code.claude.com/docs/en/cli-reference)、[Claude 程序化运行](https://code.claude.com/docs/en/headless)。使用已有订阅认证；本实现不采用需要切换 API 认证的 bare 模式。
