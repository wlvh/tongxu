## 目标

按 coding-workflow@1772cd2c 第 9 到 10 步，用一个真实 PR 跑通：固定候选的独立审核 → 需要时两路核实 → 综合 → 授权内修复 → 新候选再审；自动链内不再由人复制模型报告、手填 head 或寻找会话。

阶段 G2。方案依据 §16、§19 W5。

## 前置

W4 的结果读取与写入移交可靠；采用的分工已写入实施 Issue。

## 范围

- 转接而不是投递（对齐结论 A5）："X 本次工作明确完成 → 固定结果 → 填入 Y 的输入 → 启动 Y"。中间日志、子代理回复、标题里的 PASS 不触发下一步；只读匹配 Run 的顶层最终结果。
- 角色提示从 coding-workflow 固定版本取原文并填入 Issue、head、目标、权限；不用原型里的改写版；不静默追随上游提示变化。
- 分工：正式审核为新独立 Codex；REWORK_REQUIRED 时新 Codex 核事实与复现、新 Claude Code 核影响面与最小修复，Codex 综合；证据分歧最多三轮交换，不以模型投票裁决。
- 修复：默认按现有指令在综合后取得修复确认，修复在 Codex 验证会话进行，先完成写入责任移交（对齐结论 A4）；错误 finding 用反证复核同候选，不造空提交。
- 返工计数只计已执行并发布的修复批次（A9）；超过三次实际修复时停止自动堆轮次，生成网页端 GPT 简化反思的外部待办（A3）。
- OWNER_DECISION_REQUIRED 只暂停受影响工作；决定由 owner 写回 Issue 后重验落实。
- 解析失败是"没有有效判断"，不是第四种 verdict。

## 交付物

一个真实 PR 跑通采用流程；可控响应覆盖无问题 PASS、错误 finding、同 head 新证据、Owner 决定、格式错误、限额分支；可控响应与真实模型发现分别记录。

## 非目标

不新增固定签字层，不复制旧 PASS，不做通用流程编辑器或免审器，不做运行中投递。
