## 状态与目标

**规划级，W4 后细化。** 按已采用项目流程跑通固定候选审核→必要核实→综合→授权修复→新候选再审，自动链内不再人工搬运模型报告。规范 §16/§19 W5。

## Scope

- 先固定项目分工；采用 coding-workflow@1772cd2c 时，正式审核为新独立 Codex，有需核实问题时新 Codex 查事实／复现、新 Claude Code 查影响／最小修复，Codex 综合，证据分歧最多三轮。不能把参考流程自动覆盖目标有效政策，也不因平台新添签字层。
- 提示取固定原文并填已采用 Issue、候选、目标和权限；不采用原型缩写提示，不静默跟随 main。
- 转接是 X 本轮明确结束→固定最终结果→填入 Y→启动 Y。只接受匹配 Run 的顶层最终结果，保留自然语言报告与原始证据；无效格式不变成 PASS。
- 默认综合后确认修复；本轮已有明确自动修复授权时复用，不重复请示。只读验证会话经实际写入移交后继续修复，旧执行者未知不接管。
- 错误 finding 提供反证重审同 H，不造空提交。新 head/base/范围适用性按 §8 核对，证据可以复用，PASS 不复制。
- 只计真实已发布修复批次；超三次进入网页 GPT 简化反思，不无限堆任务。Owner 决定只暂停受影响范围；格式错误、限额等有可恢复停止点。

## 交付与验收

一个真实 PR 的采用流程；可控响应覆盖 PASS、错误 finding、同 H 新证据、Owner 决定、格式／配额边界，明确区分模型实测与夹具。T13/T19/T22—T27。独立性核对作者对话、自动记忆和隐藏状态，不仅换线程名；自动链内搬运和重复填 ID 为零。

## Non-goals

不运行中投递、不构建通用流程编辑器／免审器、不自动扩大修复权限、不把阶段完成当整个 Issue 完成。
