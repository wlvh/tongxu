正文同步自 `docs/issues/02_W1_facts_and_pr_handoff.md`。现行规范 v2.2，仍是 W0 后细化的规划级 Issue。

## 目标

只读 CLI 一次看清 PR 的 H/B、真实目标、正式范围、证据、角色与下一步，输出原 PR 交接包。W1 不启动任何模型，不发布远端，不等待 check run 或确认入口实现。

## 范围

完整分页读取 Issue/PR/评论/review/检查与已登记关系，缺页、权限、读中更新明确覆盖；固定候选保存 H/B/merge base/target/S/政策提示/本轮材料，以及存在时的共同交付与接收安排引用。H1 标签不能配 H2 diff。

区分角色、原生会话与交付；秘书/作者/独立审核/接收者不能混成一个 actor。只采集已有协调状态与相关引用，不靠关键词推定“没有冲突”或“用户批准”。没有共同交付记录就显示未登记，不要求所有历史 PR 补表。

结果包包含下一步的谁/动作/候选/缺口/后继；需要时展示新任务可能相关的在途任务、已声明共享责任、精确能力/PR 前置，不把整 Issue 未完当全部阻塞。影响清单只是线索。

发布后端无关的固定材料与交接包；作者管理 PR 正文，机器不争写状态区块。数据在仓库外，仅缓存 GitHub 事实与必要观测位置；不成为另一份可独立改写的需求。

## 验收与非目标

T01—T06、T19 的采集部分；T36/T39 的引用与缺口表达。真实只读数据＋故障夹具分别验证。共同交付 X 不是本轮全部 PR，合法 stacked 不是错误，实际目标与采用安排不符才需核对。

不写远端、不启动秘书/接收 Agent、不自动解析全历史为强制协议、不构建通用数据库／发布框架。W0 必须补 SU/代码/测试/文档触点后才编码。
