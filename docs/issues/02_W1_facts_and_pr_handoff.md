## 目标

用一个只读 CLI 把一个真实 PR 的 head、base、实际目标、最终出口、证据入口和下一步责任一次看清，并生成原 PR 交接包；未获写授权时只输出待发布包。

阶段 G1。方案依据 §4、§6、§8.1、§19 W1、§23.4。

## 前置

W0 完成，读取范围、采用规则和代码触点已定。Issue 00 的 D3、D4 有结论。

## 范围

- `tongxu inspect --repo <仓库> --readonly` 与 `tongxu collect --pr <编号> --output <隔离目录>`。
- 完整分页读取 Issue、PR、评论、review、检查；分页中断、权限不足、缺页必须显示覆盖缺口，不把未读当不存在（T02）。
- 固定候选 C：repo、PR、源 head H、实际目标引用、观测目标提交 B、merge base、采用范围 S、政策与提示版本、本轮读取的材料位置。元信息与 diff 读取之间推新 head 时不得出现 H1 配 H2（T05）。
- 原 PR 交接包按方案 §6.1 与 §6.2 两类结构生成；程序能取得的事实不让人填。
- 机器事实的落点按 Issue 00 的 D4：默认作为 check run 或 commit status 挂在 head SHA，不写 PR 正文区块。
- 每项未结束交付有下一步交接责任人：谁、做什么、作用于哪个候选、缺什么、完成后交给谁。
- 保存最小恢复信息：观测位置、游标、来源时间与观测时间分开。

## 交付物

同一真实 PR 的 H、B、实际目标、证据、下一步一次看清；故障夹具下的覆盖缺口显示；待发布交接包。

## 非目标

不启动模型，不把历史散文解析成强制协议，不要求历史 PR 全部补表，不发布任何远端写入。

## 验收入口

T01–T06、T19 的采集部分。先以真实 GitHub 只读数据和故障夹具演示，再开放有明确边界的写入。

## 评审要求

- 不从分支名猜关系；叠放 PR 指向下层分支不是错误，与意图不一致才是（T01）。
- 命令退出码 0 但部分样本失败时，从真实结果统计，作者陈述不改事实（T06）。
- 候选、证据、责任、操作记录放在仓库外的小型存储；GitHub 已有的内容只缓存，不成为可独立改写的权威。
