## 状态与目标

**规划级，W0 完成后细化为可编码 Issue。** 只读 CLI 一次看清真实 PR 的 H/B、实际目标、最终出口、材料与下一步，生成原 PR 交接包；未获写授权只输出待发布包。阶段 G1，依据现行规范 §4/§6/§8/§19 W1。

## 前置

W0 的读取范围、采用规则、代码触点和验收明确。#1 不再是待批门。**W1 不等待 check run/commit status 的最终选择或写入权限**。

## Scope

- 实现 `tongxu inspect --repo <repo> --readonly` 和 `tongxu collect --pr <id> --output <dir>`；这是待实现接口，不是当前已有命令。
- 分页读取 Issue/PR/评论/review/检查；缺页、中断、权限不足明确覆盖缺口（T02），未读取不算不存在。
- 候选保存 repo/PR/H/实际 target/B/merge base/S/政策提示版本及实际材料。H1 元信息不得混 H2 diff；私人不可读位置不声称证据可用（T05）。
- 原审核保留完整身份；patch 哈希辅助比较，不作免审。当前 base 适用性留有明确的后续接收接口，不因采集就生成 PASS。
- 交接按 §6 两类结构，程序能读到的事实不让人复填；下一步责任含谁/动作/候选/缺口/后继。
- 生成 **发布后端无关** 的机器结果包与正式证据索引。作者维护 PR body，程序不争写状态区块；check run 为后续 W3 优先路径，W1 不实现远端发布。
- 保存必要观测游标、来源／观察时间、未确认记录；数据在仓库外，GitHub 内容仅缓存不另立权威。

## Non-goals

不启动模型、不写远端、不解析全部历史散文成强制协议、不要求历史 PR 补齐新表、不构建通用数据库／发布框架。

## 验收入口

T01—T06、T19 的采集部分。用真实 GitHub 只读数据与故障夹具分别证明事实取得和失败处理；合法叠放不是错误，与采用目标不一致才需核对。工具退出 0 与样本业务通过分开。W0 需补具体 SU→代码→测试→文档后才能编码。
