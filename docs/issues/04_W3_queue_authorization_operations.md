## 目标与角色

建立条件式接收、下一步、有限授权与可靠回执。PR 接收角色独立判断，后台核权执行；秘书仅联络，不能记录 PASS、接收或直接合并。G1 可由既有接收者提供正式记录，W4 才自动驱动默认独立 Claude Code，不反向阻塞。

## 范围

接收状态及责任按规范。实质接收席位默认2可调，等待不占席位，同目标一个推进者；必要上游可提升，不打断长任务。事件触发，低频补查补漏；相同候选/计划/实质证据重复去重，不定时全合、不等 Issue 全完。

采用作者与消费者建议，独立核定最小安全合入范围：兼容基础→消费者→启用，或确必要的最小集成候选。当前接收安排绑定范围、版本、相关成员、真实目标和精确前置。新接口/计划或反例使受影响旧结论待核；新 X2 不默认阻塞 X1。

只读、逐次确认、有限委托三模式。完整匹配来源、角色、repo/target/action/S、门槛、时效/撤销和资源；本人入口与 Agent 凭据隔离。GitHub approval 可选非唯一，不能作者自批死局。不因秘书转述制造授权。有效委托内不重批。

W3 Bridge 选定实际 check run+固定详情发布；无法发布则保留报告或明确 status 路径，不自行提权、争写 PR body 或同时保留同义状态。普通后台先事务登记再调用，拒绝任意 shell/URL 代理。

合并核当前 H/target/S/plan/必要证据，用 head 条件；不声称锁 base。读回实际目标/树/提交，不符或缺失保留已合入证据待核、可补实际证据恢复；错误目标不靠测试追认，不自动回滚。未知查原操作，迟到不倒退，失联不抢写。

## 验收

T07、T13—T21、T23/T24/T32（G1）及 T37/T39—T43 的相关条件。验证作者仅声明不放行、A1 不等整个 A、不可拆组合不能分两次主干更新、空轮询不唤醒模型、计划变化旧意见不放行、秘书无接收/合并工具、已有授权不重批。

不改分支保护/认证、不复制额度、不接管生产长期进程、不建通用审批 DSL。生产先影子对照，明确 main 写权交接后接管，不双开兜底合并者。
