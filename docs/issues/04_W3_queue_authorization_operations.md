## 状态与目标

**规划级，W1/W2 后细化。** 完成测试仓库 G1 的队列、正式交接、有限授权操作、合并回读与未知恢复；本 #5 是 G1 受管接收版发布点。规范 §10—§15/§19 W3。

## 前置

W1/W2 可用；本次受管写入口的身份、授权与交接已核验。未核验则只读子版继续。#1 已归并；不要求去上游仓库先改提示，不强制 GitHub review approval。

## Scope

- 交付状态及每项下一步按 §10；实质接收席位默认两项可调，同目标一个推进过程；等待不占席位，必要上游可提升，长任务不随意中断。
- 只读、逐次、有限委托三模式。委托核对来源、角色、repo/target、动作、S、门槛、上限、时效和撤销；不能只检查开关。有效委托内不重批，越界未发不执行，已发先查结果。
- **默认设计：同序本人入口＋可恢复正式记录。** Bridge 验证人与 Agent 入口／凭据隔离、确认原始来源、repo/PR/H/target/method/S 与撤销。GitHub approval 可作为目标项目选择的来源，但核对作者不能自批、实际身份和批准语义，不能把普通 approval 扩成全部操作授权。不能同时造两套审批中心；不可验证时不开放该写入口。
- 机器结果优先由受限身份发布 check run 和固定详情，保留完整候选，不争写 PR 正文。W3 Bridge 固定实际权限路径；不具备能力则保留报告包，或明确选择 commit status+详情，不静默切换、不提升权限、不双写同义状态。
- `tongxu queue/receive/merge/reconcile` 具备明确读写模式。后端事务先登记操作及目标占用再调用；模型不能用任意 URL／shell 代理越权。
- 合并使用 head 条件。前置／目标／范围变化重新核对；不声称 API 锁 base。读回真实 merge commit、树和目标；不同／缺失显示已合入证据待核，暂停依赖证据的推进；补实际对象验证可恢复，错误目标不靠测试追认，不自动回滚。
- 响应丢失查原对象；迟到回执不倒退最新状态；重复事件不重复写。服务重启恢复原请求和占用，心跳失联不抢占。

## 验收

T07、T13—T21、T23/T24/T32 的 G1 部分。新增参数化：同 head 不同 base/范围的检查记录不能自动放行；PR 作者与 owner 相同不导致唯一 approval 死局；委托目标／范围／角色错误拒绝；合入树差异→待核→实际证据恢复；错误目标不可追认。

关闭线程、CI 绿、Ready 不清除待复核阻断；决定实施过期只重验，不要求重选。生产试点先影子对照，明确移交 main 写责任后再接管，不双开兜底合并。

## Non-goals

不改分支保护／认证、不复制额度、不接管生产长期进程、不建通用审批 DSL。发布模式无法成立不冒称 G1 受管版通过，可准确交付只读子版。
