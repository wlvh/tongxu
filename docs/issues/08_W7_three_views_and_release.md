## 状态与目标

**规划级，W6 稳定后细化。** 最终三视图、外部步骤、安装／恢复／退出与完整用户旅程；不是 HTML 方案阅读器。规范 §18—§22/§19 W7。

## Scope

- 三视图由同一核心派生：项目总览看可用能力/缺口/积压/待决；任务、会话、PR 看真实归属/状态/目标；通信与交付看原入口/请求/产物/接收/消费。不多维护一套前端布尔进度。
- 保留目前视觉与交互意图：任务树、PR 右侧抽屉、三种分配、证据导航、范围决定与授权边界；七格显示按授权合入，不固定每格一个 Agent。当前生成器仅离线源，W7 接真实状态后退役，不把模板 patch 变成生产框架。
- 本人确认可在同序入口，记录来源和实际授权边界；不默认强迫用户去 GitHub 自批。超出真实能力的操作不显示为可用。
- 已有回归：旧七缺口；新 D1 委托多维匹配、D2 实际树差异及恢复、D3 base 增量适用性、D8 分操作能力。原型断言不抵消真实端到端验收。
- 网页 GPT 技术解读、简化反思、验收计划合意为外部产物；固定输入／输出位置和版本。候选变化旧报告归历史，reject/request_evidence 不标通过。HTML 在无控制权的隔离视图。
- 安装升级前停止新写任务、保存数据库／证据引用；迁移失败可退只读，不清空／重派；平台退出仍可沿原 Issue/PR/正式证据接手。
- 区分观察覆盖、重算、代码合入、业务结果验证和正式采纳；没有分母不显示完成率。度量首反馈、通过到合入、退回原因、严重遗漏、人工操作和新增维护，不以合并数考核。

## 交付与验收

T19—T21、T28—T32 及所有受影响回归。未参与实现者只看最终三视图回答：什么可用、什么缺失、谁等谁、哪版经过什么验证、实际进入哪、需本人决定什么。真实三目标旅程与恢复手册；维护吞掉收益或 UI 误导都不能通过。

## Non-goals

不追加用量计费面板、重复汇总评论、多仓库多用户、通用流程编辑器；不拿一张全绿截图结案。
