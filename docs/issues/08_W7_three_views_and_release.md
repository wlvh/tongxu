## 目标

三个主视图从同一核心渲染；外部步骤登记入口；安装、升级与退出；旧原型缺口回归；完整现场验证；最终六个用户问题可回答。

阶段 G3。方案依据 §18、§20、§21.1、§22.4、§19 W7。

## 前置

W6 行为稳定；前端只消费核心状态，不另建状态机。

## 范围

- 项目总览：当前可用成果、剩余缺口、接收积压、有效等待、需人取舍、最近实质变化；区分观察覆盖、代码合入、已验证、重新计算、业务采纳；不给无分母的完成率。
- 任务／会话／PR：交付卡片为中心；父子、实现依赖、合入前置分别显示；接收队列与目标推进队列不混淆；七格流程条只做证据导航，"人工合并"改为"按授权合并"并显示依据。
- 通信与交付：原 PR 交接索引、关键请求、固定产物、待回复／接收／验证；无实质变化不写重复评论。
- 外部步骤：网页端 GPT 的技术解读、简化反思、验收计划合意；自动准备固定输入入口，登记输出及适用版本；候选变更后报告成历史；reject 与 request_evidence 不显示验收通过。
- 回归清单：v1 七缺口（`verification/RESULTS.md`）；产品原型三处不一致：委托未绑定范围、发出后主干前进无待核标记、判断绑定 base 的规则不一致；握手后一次授予全部能力。
- 安装、升级、退出：升级前停止接新写任务并保存本地库与证据引用；迁移失败退回只读；退出后原 PR、Issue、正式证据仍可接手。
- 收益判断按 §20.1：首次有效反馈时长、通过到合入时长、退回原因与重复类别、合入后严重遗漏、人的机械操作与决定次数、新增维护成本。

## 交付物

三视图可用；完整真实旅程、限制、收益与恢复手册；由未参与实现的使用者只看三视图回答六个问题（T31）。

## 非目标

不追加完成率、用量计费面板或重复汇总评论；不做多仓库多用户。

## 验收入口

T19–T21、T28–T32 及所有受影响回归。

## 评审要求

- 后台安全但页面误导，T31 不通过；功能可用但新增维护吞掉节省，T32 不通过。
- 报告 HTML 在无控制权限的隔离视图呈现（§15.3）。
