## 目标

形成同序开工前的事实与政策基线：试点项目的接收流程、主干写入者、有限委托、资源账本、现有检查工具与材料、在途 PR 与下一步责任；产出 W1 的 Target State Bridge 和一份按 Issue Agent 规则可编码的 W1 Issue 草稿。

阶段 G0。只读。方案依据 `docs/tongxu_v2_plan.md` §19 W0、§23.1。

## 前置

- #1 的 D5（确认载体）和 D7（试点对象）至少有结论；其余可带着未决项做。
- 只读访问试点仓库与本仓库即可，不需要任何执行器接口。

## 范围

1. 固定工作流参考版本 coding-workflow@1772cd2c，核对试点项目既有接收、主干写入、有限委托与资源账本；冲突写明适用范围。不从共享 GitHub 账号的文字推定人的新授权。
2. 读取一组在途或固定历史 PR，复原实际目标、依赖、证据入口与下一步责任；不完整读取必须标明；不做无来源的完成率。
3. 盘点已存在的验收入口及材料可用性。已有工具优先复用；候选实现是否可用依实际合入和接口核查。
4. 形成 W1 Target State Bridge：代码触点、复用或新增理由、权限、失败恢复、正式测试入口、文档影响；给出 T01–T06 的覆盖办法。
5. 按 Issue Agent 规则写 W1 实施 Issue 草稿：目标、非目标、Spec Unit、验收、授权与未决项。

## 交付物

- 一份真实基线文档，区分实测、读码推断、引用历史记录与未检查。
- W1 Bridge 与 W1 可编码 Issue 草稿，提交到 `docs/`。
- 技术栈与产品仓库建议：默认 Node LTS、TypeScript、SQLite；本仓库是否直接作为产品仓库由 owner 定。

## 非目标

不接管生产会话，不改权限，不建新仓库，不重做试点项目已有工具，不批量开 W0–W7 的并行工程，不做执行器探针。
