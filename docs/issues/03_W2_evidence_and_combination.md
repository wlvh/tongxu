**规划级，W1 候选语义稳定后细化。** 在隔离现场对固定 B＋H 运行项目已有检查，呈现内容与覆盖变化，不改作者分支。阶段 G1，规范 §7—§9/§13/§19 W2。

## 前置与范围

- W1 固定材料与实际工具入口可取得；不等待 #1 逐项确认。
- `tongxu verify --candidate <C> --check <registered>`：入口、参数、读写边界明确登记，数组传参，不拼模型 shell。
- 用已验证的 `git merge-tree --write-tree` 计算 T，隔离执行；有冲突交回负责人。记录 B/H/T/方法/Git、工具和输入。只写临时对象不改作者工作区/index/分支；若检查依赖 HEAD，建立正确候选提交或明确证据范围，不能把 read-tree 内容冒充 HEAD。
- 接入已有工具而非复制业务。输出真实分类、内容／来源／范围差异、缺材料／工具错误；D02 类别只作该适配示例，不硬编码到通用核心。
- 保留原审核证据与当前 base 增量判断的接口。工具成功不能自动承诺审核适用，闭包／路径交集只提示。
- 工具负例包括漏样本、空样本、丢来源／范围、工作进程失败、输入被修改。复用既有场景，不建第二准备器。

## 交付与验收

实际检查可重跑；组合不改作者现场；内容变化、不完整和故障可见；原始证据和受测对象同源。T08—T12、T14/T16 的相关部分，T17 的测试凭据隔离。已有语义反例证明 patch 相同／无冲突不等于组合正确；树相同也不等于环境和外部数据相同。

## Non-goals

不新增真实付费请求、不复制业务、不做万能依赖分析、不自动 cherry-pick/rebase/push。昂贵验证可按明确风险抽样，但必须保留未覆盖范围。
