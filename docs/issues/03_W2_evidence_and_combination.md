## 目标

接入试点项目已有的检查入口，在隔离现场对"固定目标 B 加候选 H"的组合运行检查，输出内容与覆盖分类；不改作者分支，不重造测试平台。

阶段 G1。方案依据 §9、§13.3、§13.4、§19 W2。

## 前置

W1 的候选与材料稳定；项目原测试入口可取得；Issue 00 的 D3 有结论。

## 范围

- `tongxu verify --candidate <固定候选> --check <已登记入口>`。命令入口、工作目录、参数与允许读写范围在配置里注册，参数按数组传递，不把模型消息拼成 shell（§15.3）。
- 用 `git merge-tree --write-tree` 计算 B 加 H 的组合树 T，`read-tree` 进隔离 worktree 运行检查；文本冲突交回责任人；记录 B、H、T、合并方法、工具版本、输入与测试入口。已实测：它向对象库写树，工作区与 index 不动，冲突时退出 1（`verification/merge_tree/test.sh`）。
- 输出方案 §9 的分类：SAME_OK、CHANGED_OK、FAIL_TO_OK、OK_TO_FAIL、SAME_FAIL、CHANGED_FAIL、NOT_COMPARED／工具故障／缺材料。缺一份材料显示不完整，不显示"没有变化"。
- 工具自身的负例：漏样本、空样本、丢来源或范围、工作进程崩溃、输入被改动（T10）。
- 把 `verification/semantic_conflict/repro.sh` 作为 T12 夹具：patch 相同、路径不重叠、组合反例仍阻断；闭包碰撞只作提示。

## 交付物

一个实际检查可重跑；组合不改作者分支；内容变化、缺材料和工具故障可见；原始输出与版本同源可查。

## 非目标

不复制业务实现，不跑新的真实付费请求，不建设全语言依赖分析，不自动 cherry-pick、rebase 或 push 作者分支。

## 验收入口

T08–T12、T14、T16。

## 评审要求

- 退出码 0 不等于业务通过；树相同不等于依赖、环境、外部数据相同（§13.3）。
- 测试进程不携带发布凭据；候选代码里的脚本拿不到发布身份（T17）。
- 昂贵测试可按明确风险抽样，但记录抽样依据与未覆盖项（§8.2）。
