## 目标

两种原生执行器准确运行与回执，同时落实两个具体角色：工作秘书默认独立 Codex App Server，只查询/联络/跟进；PR 接收默认独立 Claude Code CLI，可技术接收和请求受管合并。角色身份、上下文和权限不同。

## 范围

分别实测指定 session/turn/workspace、两轮输入、最终结果、等待/失败、批准转交、核实到授权修复连续性。能力是已验证版本操作与本次身份/状态的交集，不从创建推出全能，不按最近会话接续，错误 turn 不降级成新轮次。

按 `prompts/README.md` 装配公共规则、单角色、适用固定上游提示和可信输入；记录版本与实际能力。秘书通过同序受限工具，不开放任意 shell、业务写入、测试、审核/接收 verdict、合并或授权。后端拒绝错误角色请求；仅 prompt 自律不算通过。所选原生模式无法限制内置工具时关闭秘书控制模式并报告，不伪装已隔离。

秘书先实现全局只读、定向联系与未完跟进；接收角色读取固定包、返回匹配候选的接收判断，后台执行仍在 W3。运行中跨工具投递产品化留 W6。原生认证/订阅/费用按实际路径核验，不自动购买 API 或改变个人账号。

已有长期会话只关联/观察，不迁移或夺取控制；暂停请求、实际停止与后台命令结束分开。秘书停机不取消已授权后台工作；重建上下文重新读事实与跟进。

## 验收

T17/T19/T22/T26/T27，加 T33/T34/T35（运行恢复部分）/T44。两引擎真实事件、角色工具清单、上下文隔离、错误工具请求拒绝和缺能力说明。不以离线原型或结构化 JSON 冒充真实 Agent 接通。
