## 目标

验证并实现 Codex 与 Claude Code 两种执行器的启动、指定接续、最终事件读取、原生批准处理与失败语义，取得准确的 session／turn 标识与结果；能力按已验证的具体操作开放。

阶段 G2。方案依据 §16、§17.2、§19 W4。

## 前置

G1 可用。原生认证、CLI 版本、预算与测试任务另外固定。#1 的 D8 有结论。

## 已核过的接口事实（2026-10-17，官方文档）

- Codex App Server：`thread/start`、`thread/resume`、`thread/fork`、`turn/start`、`turn/steer`、`turn/interrupt`。`turn/steer` 要求 `expectedTurnId` 匹配活跃轮次，无活跃轮次失败；id 不匹配时的行为文档未写明，必须实测，且不得降级为启动新轮次。批准是服务端向客户端的请求，需要有客户端接住。
- Claude Code：`-p` 加 JSON／stream-json；指定会话的后续轮次；每个会话绑定本机 inbox socket（`CLAUDE_CODE_MESSAGING_SOCKET`），脚本可投递，运行中会话在工具调用之间读，空闲会话由消息开启轮次，结果分 Delivered、Held、Refused；`-p` 工作进程可收。
- Claude Agent SDK 文档原文：未经批准，第三方开发者不得为其产品提供 claude.ai 登录或额度。本机自己账号驱动 CLI 子进程是否受此约束按条款核，不预设沿用订阅。

## 范围

- 两个适配器：启动新会话并取得真实 ID 与工作区；按 ID 接续；两轮输入；读取顶层最终结果而不是中间日志；运行事件与状态查询；批准请求的转交或明确停等；中断与暂停按实际支持接入。
- 能力分级：已关联、可观察、可控制；每项控制能力在该操作实测通过后才开放，握手只给观察。
- 探针在独立测试会话完成；已有长期会话只关联与观察，不重启、迁移或夺取控制。
- 认证与费用路径按最终选择的具体路径验证并记录。

## 交付物

两种真实引擎的准确 session／turn 与结果读回；能力表按操作填写；失败说明影响哪个后续动作，不反向阻塞 G1。

## 非目标

不重启旧会话，不用新建会话冒充接续，不默认购买 API，不自动接受全部批准，不统一执行器抽象后强迫原生工具适配。
