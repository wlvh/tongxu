## 目标

三个顶层责任、三种子任务派发、同工具与跨工具的消息与固定产物消费，在真实多任务上成立；不新开竞争写入者，不强制集成分支。

阶段 G3。方案依据 §17、§13.1、§19 W6。

## 前置

G2 可用；确实出现多工作项与可用投递路径。

## 范围

- 三种派发：同工具新会话、另一工具新会话、并入负责人待办。并入不开启同一工作区的第二个写进程，之后可有顺序 Run。
- 派发去重两个维度：工作项已有未结束或未知的写入尝试；会话或工作区正在写入。产品原型已有工作区占用与路径规范化检查，沿用并加上会话写入锁。
- 每个子任务声明允许触碰的路径，交付时用变更文件列表核对（A15）；路径不重叠不代表语义不冲突。
- 寻址：提问与协调按 Issue 加角色；写入与投递精确到会话、机器、工作区、本次执行标识（A7）。不用"最近会话"定位。
- 消息状态：待投递、发送中、送达、暂存、拒绝、未知、回复。同工具优先原生通道（Claude inbox socket；Codex 按 W4 实测），跨工具由适配层转交；发送者来自真实连接，不由模型自报。重复事件合并到原消息。
- 产物三态：已登记、已接收、已验证。接收需版本匹配且能读取；验证需经实际消费入口，证据从执行器事件或工具输出取得（A14）；人工复制只算调试。
- 范围变化只经有效决定写回 Issue 后采用（A6）；普通技术讨论不改采用范围。
- 集成分支可选（A8）；数据包依赖不变成代码分支依赖。

## 交付物

三个顶层责任至少一条真实跨工具消费；并入待办没有竞争写入；一条直接合入路径与一条确需集成的路径。

## 非目标

不强制父任务集成分支，不建新对象存储，不猜测原生内部子代理，不做统一聊天。

## 验收入口

T07、T20、T26–T30。

## 评审要求

- 角色换会话不偷偷重定向未知消息（T29）。
- 中途更换一个已确认退出的会话，新 Agent 只凭 Issue、原 PR 与证据接手（T20）。
