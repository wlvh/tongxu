## 目标

新任务接入已有开发、过程持续沟通、共同交付与精确 PR 合入前置，在真实同／跨工具协作成立。秘书安排联系，开发方定技术边界，独立接收角色定安全候选；普通后台投递与执行。

## 范围

新任务登记→读取相关在途任务/实际代码并询问未提交工作→相关 A/B 核对接口、失败/复用、写责任、材料与消费者→接收角色核必要交付安排→采用后允许相应共享写入。未回复不算同意，未对齐只暂停冲突部分，独立工作继续；小独立任务不套普遍审批。

共同交付记录在已有主 Issue 验收部分，有范围和安排版本、技术牵头、参与任务、具体能力/PR 的开发/合入/启用条件。接口、来源、保存/复用、新实质反例和新增依赖变化触发受影响反馈重核；迟到旧回复不放行。新 X2 不静默扩大 X1。

三种派发：同工具新会话、另一工具新会话、并入原待办。任务范围、规范化机器/工作区和发布分支由后台事务检查；未知不释放。不用前端按钮承担真实锁。

任务自主联系，后台中转，不经秘书改写/审批。发送者来自连接，按角色定位准确会话；同工具复用可靠原生通道不重复投递，跨工具适配。GitHub 保存正式决定/交付，发布成功不冒充原会话送达。秘书离线通信仍成立。

消息送达/暂存/拒绝/未知/回复分开；旧未知消息不随负责人换会话改投。产物登记/匹配读取/实际消费分别验证；原消息和 Operation 同步回查。数据依赖不强制代码分支依赖。

## 验收

T07/T20/T26—T30，加 T35—T43。真实 A 在途未提交、新 B 协调、原消息双向反馈、精确前置、秘书离线继续、X2 不扩大 X1。直接安全路径和最小集成路径分别覆盖。成员 PR 全合但用户场景未验时 X 不完成。

不建设对象存储、万能冲突预测、全机进程锁、全量聊天镜像或新增上级 Agent；人工复制只用于调试不能作为自动交接通过。
