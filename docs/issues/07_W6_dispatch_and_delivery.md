# W6：两个固定接收任务的阶段协作

本子范围在已有真实执行器、原队列接收、发布和受限秘书基础上，细化 #8 的一个可执行片段。固定前置为 PR24 `e5ca71fa4883b0546758d3e6c0b793e8fdc806a1`，独立分支 `feat/w6-paired-reception`，真实 target `feat/w4-readonly-secretary`。独立双任务示例是两个固定候选 A/B 的接收工作；仅 B 的共享接收阶段等 A 的指定独立判断，不等整个上游 Issue 关闭或合并。

本批既有本人边界不变：同序本地开发和限定验证；现有订阅，不新认证或费用；不 main/merge/自批/部署，不操作 SEC_metrics。技术顺序由既有持续开发委托细化。本条不是本人生产采用、完整 G2/G3 验收或新增写权。

CP01 一个入口固定同一原队列中的两个不同 item、各自候选/材料包、接收计划 hash、共同范围来源与阶段安排。任务 A 形成指定能力的接收结果；任务 B 对使用它的当前候选完成接收。运行前核两个计划、实际当前材料及已有占用，保存原计划。禁止模型报告改变执行器、权限、候选、路径或顺序。

CP02 B 的本地材料检查可在 A 原生接收进行时完成；B 的共享接收明确等待 A 的当前、完整、范围内接受结果。B 先检查不会消耗接收席位等待 A；原任务 A 的其他实施、Issue 关闭和合并不作为该门。普通失败保留具体原因，不能将证据不足或部分结果当已满足。

CP03 后端在 B 准备和实际发送前重核 A 的准确 item/packet/H/绑定/判断及停止与占用；A/B 候选或材料变化只使相应新阶段待核，不改写历史结论。同库原客户端也不能绕过新增阶段门派发。仍复用原 events/blobs/operations/claims/controls，不创建独立调度账本。

CP04 程序将 A 的完整判断与准确原引用作为数据加入 B 的固定输入，保存其 hash。B 返回明确的消费引用与完整报告；仅文件存在、发送成功或退出 0 不算实际消费。A 报告没有工具或指令权限。对无必要发现的结果不制造返工。

CP05 同一入口重复只读取/核对原运行。等待、中断、错误终态、捕获缺失、未知原进程都不能换目录或新 operation 重发。原执行确已结束且捕获完整时，依现有 reconcile 继续；部分结果保持未知并保留原现场。停止新增投入作用于后续新模型发送，已有原件和独立本地读取仍可访问；停止实施/合并不偷换成暂停所有只读工作。

CP06 使用明确标记的本地样例验证阶段阻止、独立步骤继续、同库跨进程竞争、重复、材料变化、撤销与中断恢复。固定候选经必要独立复核后，运行一次真实 A/B 接收与产物消费；保存实际执行版本、两个原会话、完整输入/输出、原操作和消费关联。真实与样例证据分开。首片段只支持两个固定只读接收任务；不宣称任意开发任务调度、共享代码写权转移、统一负责人、所有 W6 或完整 G3 已完成。

源触点：queue-store.ts 的原账本及阶段检查；receiver.ts 的输入/消费绑定；新增 paired-reception.ts 与固定 CLI；W6 定向回归。源文档与原 #8 实施条款发布读回后编码；PR24 保持独立可接收。

## 范围

秘书找相关人，负责人核实际代码和未提交工作，优先选并行／阶段串行／统一负责人。仅共享部分约定接口、失败／复用、写责任、消费者与材料；小独立任务无普遍审批。人采用S，团队可在范围内更新r；未回复不算同意。

阶段串行B共享实施等A1，不等整个A；独立调查继续。统一负责人先核旧Run／未提交现场／后台副作用／远端再移交；未知不抢占，不循环等待。后台在派发、写入和后续阶段重新核组织门、停止状态、授权和占用，非前端提醒。

三种派发同工具新会话／另一工具新会话／原负责人待办保持；后者顺序执行无竞争写者。任务自主联系，后台中转，不经秘书改写审批；同工具复用可靠通道不双发，GitHub保正式依据不是日常消息队列。

X1共同成果和开发／合入／启用条件分开；X2不扩大X1。接口或反例更新只重核受影响当前反馈，消息送达／实际消费分别证明；未知旧消息不改收件人。秘书离线、收回新合并时独立技术协作仍可继续。
