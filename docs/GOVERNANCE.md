# 治理补充 v2.4｜候选，须经本 PR 采用

本文件补充 v2.3，不撤销原有角色、唯一写入、证据绑定、未知恢复与 W0 停止点。当前分支包含可审阅的设计和离线交互，不表示 main 已采用，不表示分支保护或真实 Agent 已启用。实施前读取目标项目当前有效规则；本次修改必须按 base 上的旧规则审查，不能用候选自己的新规则为自己放行。

## 1. 谁能修改约束

所有同序代码与规范修改走独立分支和 PR，包括本次，不直接更新 main。修改授权不自动豁免已有 PR 要求。边界变化应先说明旧规则、新规则、允许／禁止行为如何变化、影响的已有委托和恢复安排，再由可信本人入口作相应采用；技术约定与事实纠错可在已有委托内通过独立接收，不要求所有 PR 由人逐次批准。

必须一起保护的对象是：规则本身、CODEOWNERS、检查／发布工作流、规则判定及工具权限实现、能够改变这些要求的仓库管理权限。Agent 不持有修改 ruleset、关闭保护或解除自己阻断 review 的权限。程序的规则判定使用受信任 base 版本，候选不得替换判定器后证明自己合规。路径命中只是保守筛选；改到其他路径也可能改变授权行为，不能以未命中自动免审。

建议复用 GitHub 的 require-PR 与 code-owner review：main 不允许普通直推／强推／删除；核对管理员和 App 的 bypass；边界路径由本人批准，其他路径按既有独立审核／委托。现有混合文件保守列为边界路径，可能带来额外人工审核；后续确有负担再拆分，不建立自然语言“自动修宪判定器”。CODEOWNERS 自身也在保护范围。

## 2. 本批目标怎样落到 GitHub

默认以 Milestone 组织一批用户成果，描述含主 Issue 链接及目标摘要；具体本人采用 S、团队约定 r、验收和历史证据仍在该主 Issue／原 PR。平台保存 GitHub ID、采用时的实际文本快照和来源，不建立第二份可独立编辑的目标。

Milestone 是分组，不是批准。改描述、挂入 Issue、把里程碑关闭都不能证明本人采用或功能完成；不得凭显示的 wlvh 作者推定人类意图。S 的改动另核可信来源与作用范围。GitHub Issue／PR 的 milestone 归属是单值；一个长期 Issue 参与 X1/X2 或已有发布里程碑时，保留其归属并在主 Issue 按交付引用，不强制移动或为格式制造子 Issue。Milestone 尚未使用时，现有主 Issue 就可开始，不以迁移为前置。

## 3. 决定可以复用，但判例不能扩权

复用项目已有 decisions.md；没有时使用 docs/decisions.md 的最小索引。决定记录含编号、提出／采用／撤销状态、原始来源、适用项目／目标／后果边界、明确例外、替代关系。采用后的原文保留，后续通过新记录补充或替代。模型摘要仅为导航，不能自己标 adopted。

负责人或接收者先找适用记录，说明本次与判例相同的条件，以及新增的差异。条件相符且委托仍有效可直接处理并引用；存在差异时先判断是否仍在现有技术委托内，只有真正越界才升级。不把“以前允许一次付费”当成长期预算，也不能因找不到判例就把普通技术选择都交人。新确认不再让同一个决定在多处重签。

观察同类已覆盖事项的不必要升级是否减少，并同时看越权、严重遗漏、任务构成与真实使用；总升级次数下降不能单独证明成功。需求越新、风险越高，合理升级可能增加。

## 4. 动作与后果一起授权

权限不是 action 名字或风险分数二选一，而是角色＋动作＋精确对象／环境＋后果边界＋资源＋有效期／撤销。每次动作列明：改哪份对象，是否触发自动部署、外发、付费消费、数据修改；范围多大；可逆步骤是什么；撤销后哪些已经发生、仍须处置。不能用“可逆性×范围”相乘生成一个全能阈值。

后台可以取得实际目标、工作流触发器、环境规则和已登记消费者线索；完整语义后果仍需技术负责人核查。未知关键后果不能自动记为低风险；仅阻止受影响的扩大性动作，独立只读继续。检查 Git 回退可行不代表邮件可收回、数据可恢复、费用可退款；所谓未发布分支也可能触发 CI 或外部自动消费者。

停止新实施不等于零成本或即时杀进程。停止／撤销只阻止相应新动作，已发送、运行中、已发生和未知分别展示。已合未发布代码默认保留、明确禁用后续未授权发布，不自动回滚；不能可靠隔离发布触发时，合并本身须覆盖该后果。恢复新开发不恢复合并／费用权。

## 5. 模型／提示／工具变更后的有限回放

记录角色、请求的模型别名、实际可观测版本、prompt／工具配置、候选／材料／环境；别名不是不可变版本。可观测变化触发该角色的重验证；无法识别供应商静默变化时明确可观测性缺口，用有界复测与结果监测补充，不承诺能发现每次更新。

先从真实已核实历史候选选择 3—5 个代表性哨兵样本，固定输入、已知适用断言、反例和限制，包含应该通过、应该拒绝、误报反证、权限边界／共同消费者等适合该角色的情形。此数量是启动建议，不是完整标定或全部历史结论的正确性证明。缺真实样本就标未建立，不虚构黄金集。回放者先看契约和材料、独立给判断，再对照已保留的 scoped expected assertions；不把答案提前喂给它。

变化不抹去旧版本历史证据，也不一刀切撤回所有角色权限。按事前采用的策略，让受影响角色的新高后果动作暂回人工／独立接收或只读；既有运行和未知副作用保持恢复路径。绿色哨兵只解除策略中约定的有限限制，不授予新权力。严重异常维持限制，独立核实；不得由更改模型的同一任务修改期望答案把回放变绿。回放仍受现有额度／材料权限约束，本次不调用真实模型。

## 6. 不依赖风险标签的盲抽查

在风险定向检查之外，对全部满足既定资格的放行候选设置一个非零、预先约定的随机抽查概率；例如 p=0.1 只是待采用参数，不是现在的调用授权。由受管后台在候选首次达到抽样时点抽签并持久保存，作者／模型不得挑选、重复抽签或通过重复事件增加样本。变更范围和已发生事件必须有身份；漏样本、预算不足、工具失败分别记为未检查，不归入通过分母。

独立复审先取得同一固定代码、契约、环境与原始输入，不看原 PASS、风险标签及作者结论；提交自己的结论后才对照旧判断。独立性不以换厂商名字自证，应检查上下文、材料和工具边界。不同模型可降低某些共同错误的机会，但不是独立随机仪器的保证。

抽查通常是固定已合入候选的只读复审，不能逆转已发生后果；高后果动作仍需要事前对应检查。哪些被抽中必须等复审才能发布，按原策略规定，不事后增加全项目阻塞。发现严重问题只限制受影响链路并安排复验。随机覆盖不能保证必定发现盲区，风险检查也不是永远发现不了；二者互补。比例、时点、预算调整有采用记录，不新建评估平台。

## 7. 控制指令怎样让人看懂并确认

重要控制在生效前回显人可读的变更：对象／本批版本；旧→新；哪些阶段受影响；哪些继续；后果／费用；依据／判例；已发动作。本人确认这一个结构，记录原话和确认对象。确认时若候选、组织、范围、授权或关键后果已变，拒绝旧确认，重新展示差异。

查询、消息澄清和已预授权低风险协调不反复弹框；明确按钮已经给全对象和后果时不再同义确认第二次。已认证的紧急“停止新动作／收回委托”应立即登记并限制，不等待秘书再确认；只阻止新动作，不声称已终止原运行。恢复、扩权、改变目标和发布等仍有相应确认。秘书文本永远不能自己点击人的批准；UI 演练里的 actor 字符串不是生产认证。
