# 原任务角色提出有限联系请求

对应唯一当前余项 `completion-coverage.json.currentRemainder.items[F01]`（原T38，关联T28/T29/T35）。原 A 保持负责人，秘书不参与逐句转发。正常 f847 试用和已固定的原退回结果保持。

用户从已登记任务入口启动原 A。A 读取实际材料，需要联系时在完整回复中返回固定格式的联系请求及预登记 ID；无需联系时返回原格式的完整报告，后台不启动其他角色。后台核原最终捕获与任务材料，再沿原 TaskInbox 给准确 B 投递固定问题和 A 的完整原文；B 完整回复及消费确认返回后，程序交回原 A 综合。新会话如实记录，不把同一负责人写成同一原生会话。没有联系需要时不启动 B。

可信计划固定原 A、有限选项（最多8项）、每项 B 的任务/角色/执行程序/输入/授权和回 A 的请求。模型只选择 ID，不提供任务、路径、命令、新权限或收费渠道。整个计划摘要进入原 A 的固定输入，改选项或后续模板不能复用已登记 A 请求。原报告只是选择和证据，不是权限来源；实际发送继续核原候选、责任、停止、资源、认证用量和执行边界。

状态与全文从原 TaskInbox、消息计划、捕获、消费回执和资源结果重建；不另建发送账本。只有完成且已核原捕获的 A 回复可触发 B，只有 B 完整且资源结果已核才能回 A。已发未知不重发、不改收件人；关闭入口不启动下一阶段。重入先核同一原运行，保留全部失败、等待和部分结果。

联系选择使用现有只读角色的结构化报告通道，不新增 shell、网络、任意工具或通用调度。最初选择报告不是组织协调已完成的证明；需要协调反馈时，最终原 A 的完整反馈仍走原协调消费者。普通的固定 A→B→A 入口和旧捕获继续可用。

本轮验证以一次实际需要的联系和完整回读为主；另核不联系、未知选项/角色、旧候选、停止、重复/并发、已发未知和关闭后不派发。真实原生选择及回读与明确故障夹具分开。V01的在途写者/未提交共享工作证据按同一实际关系补齐，优先复用现有写责机制，不另写接管平台。本文是实现契约，不是验收通过。

初始请求保存明确的联系选择标记及整个计划摘要；有组织协调材料时，选择请求与最终协调反馈的输出契约分别说明。选择本身不记为共享部分通过；B与最终A的正常反馈仍由原协调消费者核验。页面启动前可展开查看固定联系项、实际工具/角色及问题；完整报告保留准确原run、会话、轮次、原文与消费关系。
