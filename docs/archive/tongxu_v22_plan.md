# 同序 v2.2｜工作秘书、任务协作与条件式交付

**现行产品与实施基线。** 本轮依据用户新增的秘书定位、新任务与在途工作协调、PR 条件式合入要求修订。这里交付设计、角色指令和离线交互，不宣称应用、原生执行器或生产权限已经实现。v2.1 存档在 `archive/tongxu_v21_plan.md`；历史评审不是并行规则。文件名保留供已有链接使用。

## 01｜产品与实施边界

产品仓库 `wlvh/tongxu`，只读试点 `wlvh/SEC_metrics`。当前开发入口仍为 #2 / W0，先读取当前 Issue 和新评论；不扩大为试点写入、接管原会话、业务调用或合并授权。W0 已在执行时，只核对本修订的增量，不重新开一份重复任务。

用户主要和工作秘书交谈，也能直接操作工作台。开发在原生 Codex／Claude Code；正式任务依据在 Issue，代码交接在原 PR。工作台不是新编辑器或终端。**设置有全局视野的秘书，不设置拥有全部技术和授权权力的全局主裁判。**

## 02｜角色与默认运行绑定

| 角色 | 默认运行入口 | 做什么 | 禁止 |
|---|---|---|---|
| 工作秘书 | 独立 Codex 会话，经本地 App Server；MCP/受限工具连接同序 | 总览、联络、分派已明确且获准的工作、跟进、整理待决与成果 | 写业务代码、运行测试、技术验收、改 PASS、处理冲突、直接合并、任意 shell |
| Issue 交付负责人 | 每项独立 Codex 或 Claude Code 原生会话 | 技术调查、协调共享边界、方案与实现、子任务、完整交付 | 自行扩大产品范围／费用／主干权力 |
| 子任务实现者 | 独立原生会话或负责人顺序待办 | 在明确范围内实现、自测、固定产物交接 | 把局部完成当共同目标完成 |
| 独立审核者 | 采用固定工作流时使用新的独立 Codex 上下文 | 固定候选的代码、测试、契约与复杂度判断 | 继承作者聊天或被秘书催办替代判断 |
| Finding 核实者 | Codex 查事实；独立 Claude Code 查影响，按采用流程 | 复现、反证、影响、综合后的授权内修复 | 用格式或模型投票判真伪 |
| PR 接收／集成 Agent | 独立 Claude Code 会话，程序化 CLI 与准确接续 | 提前核对接收设计、消费者与组合验证、退回／接受、提出候选合入请求 | 代替 Owner 扩范围／付费／部署；接受自己实现的代码而不独立复核 |
| 执行后台 | 普通程序，无模型 | 寻址、队列、身份核对、工具执行、有限发布与合并、记录与恢复 | 根据一句模型结论跳过门槛 |

角色稳定不要求进程永久在线。接收 Agent 自己提交修补时，这部分另由独立审核／接收上下文复核。秘书与任务间不共享隐藏会话状态。模型和版本是配置，默认引擎是本产品选择，不是能力优劣结论。

`prompts/README.md` 为角色提示装配入口；`prompts/runtime_contract.md` 规定输入与工具边界。当前仅模板与接口约定；未注册工具不能假称已可调用。原生参数、权限、订阅与 API 费用必须在 W4 实测核验，不自动采购或切换认证。

## 03｜阶段与范围

G0/W0：事实基线、W1 Bridge 和可编码 Issue。G1/W1—W3：GitHub 交付接收、固定材料、已有检查、临时组合、下一步、队列与授权操作。G2/W4—W5：两引擎运行适配，秘书最小联络／查询与独立接收角色绑定，审核循环结果自动转接。G3/W6—W7：新任务接入、持续通信、共同交付与最终界面完整实测。

G1 可以复用原生工具中既有接收者，不等秘书自动运行；G2 不能冒称完整运行中投递。W1 起的数据要能表达角色、新任务协调和共同交付的引用，但不先建设整个 G3。首个部署仍是单用户、单仓库、单台已验证主机。三个顶层责任是验收示例，不是数量限制。

不做通用审批 DSL、万能影响／免审器、跨主机控制、多仓库多用户、自动 rebase 作者分支、统一全部原生聊天、第二本业务额度账。不无条件自动合并；有效有限委托内的技术合并可以推进。

## 04｜工作秘书与人机交互

首页为秘书对话和三类卡片：需要你决定、正在跟进、已经交付。原项目总览、任务／会话／PR、通信与交付继续存在；秘书调用与按钮相同的后端接口，不另立数据源。

秘书读任务／PR／证据索引、实际运行与原始回执，默认不吞下全部聊天。需要技术解释时找责任人，不自行调查业务代码或运行测试。收到新任务先保留用户原意及范围，交给开发负责人判断影响和技术方案。可提出协调优先级，不成为技术上级。

明确已授权的低风险联络和安排不反复弹确认；新目标、费用、权限、失败含义、正式采纳／部署等仍需用户有效决定。秘书仅转录确认来源，不能用自己的总结证明授权。响应区分已登记／已投递／对方接续／待核／完成，必须关联实际操作。未知自然语言不得映射任意命令。

秘书停止或重建上下文不影响已授权任务、消息投递、接收和回读。它恢复后读正式状态及未完跟进，不靠旧摘要续写事实。实质例外即时提醒，普通进展集中汇报；没有变化不空转和刷“收到”。关闭浏览器不是取消任务；主机关机不承诺继续运行。

## 05｜唯一正式来源与消息通道

Issue：目标、采用范围、共同验收和正式决定。原 PR：本次代码交付、接收／退回、固定证据。项目索引：责任与授权入口、跨任务等待。原生引擎：实际 session/turn/工具事件。原账本：预算／预留／认领／消耗。平台：引用、观测、队列、请求与恢复，不成为独立需求或预算。

**Agent 自主联系，后台中转，不经过秘书逐句判断。**发送方提出关联任务的请求，后台核身份，按工作项→角色→准确会话投递；同工具可靠原生通道可复用，不重复发送；跨工具使用适配层。GitHub 不是日常消息总线。

技术澄清走工作台。改变采用范围、正式交付、退回与验收结论先落原 Issue／PR，工作台发送链接通知。无法发布正式记录时显示待发布，不能采用本地草稿去扩大写范围。远端只发评论而无会话回执，只能说记录已发布，不能说 Agent 已收到。

## 06｜新任务接入与在途工作协调

新任务登记后可调查，不应立即开始可能冲突的共享写入。秘书依据现有分工、PR、登记依赖和变化线索找相关负责人；文件交集不是完整影响证明。新负责人必须读取实际代码并联系既有负责人，特别核对尚未提交的工作；未回复不是同意。

只对相关共享部分形成短约定：共同用户目标；谁写共享模块；接口输入／输出／单位／期间／来源及错误含义；谁验证消费者；材料位置；哪些步骤可先做；精确开发／合入／启用前置。由开发方提出，相关消费者和接收角色补盲点，正式落在已有 Acceptance Checklist。独立小任务不增加普遍开工审批。

接入状态应区分已提出、已联系、待当前版反馈、部分可继续、共享边界可实施。责任／契约／范围变化后旧反馈保留为历史，不能放行新范围。相关方无法取得回执时，暂停冲突部分，独立调查、材料与非相关工作继续。秘书不替双方判接口，也不把未提交口述当交付证据。

开发中在公共接口、错误语义、来源选择、保存／复用、共享写入、实际新增依赖或新反例发生实质变化时通知受影响方和接收者；不要求固定频率互相报到。范围或成本冲突才经秘书提交 Owner，普通实现问题由技术负责人解决。

## 07｜共同交付与三类前置

共同交付 X 是一批用户能力，不等于一个 Issue，也不等于所有参与 Issue 的全部代码。每批选择一位已有技术负责人牵头，不新增上级管理 Agent。秘书跟进；接收者负责该批的独立接收安排。

记录在已有主 Issue 的验收部分：本批目标与非目标、参与任务／负责人、共享约定、固定材料与测试入口、预期差异、初步 PR 顺序和真正完成条件。初期可引用能力而非猜 PR 编号；PR 产生后绑定真实对象。局部材料、代码与能力分别记录。

开发依赖：B 需要 A 的哪项接口或材料才能继续某一步。合入前置：当前候选进入实际目标需要哪些代码／证据。启用前置：用户入口或正式发布前还需哪些组合／操作。这三种关系与父子归属分开，数据依赖不自动成为分支依赖。

新需求默认列为下一批 X2，不自动扩大已接近完成的 X1。原 Issue 很大时，B 只等 A 的兼容接口 PR，不等 A 整个 Issue 关闭。成员／范围／目标变化有版本，旧接收安排不能放行新组合；新反例即使代码不变也能触发受影响复核。

## 08｜谁决定合入与何时处理

作者主动提交合入建议：属于哪批交付、本 PR 提供什么、需要哪些固定前置、哪些不必等、消费者反馈与实际证据、建议顺序。相关负责人核对自身依赖；接收 Agent 独立判断最小安全合入范围。作者声明不是自动批准，不要求每个 PR 固定三人签字。

事件触发为主，低频补查补漏。提交接收、新 head、检查完成、前置到位、消费者反馈或有效决定触发核对；重复事件按候选及安排版本去重，没有变化不重复叫模型。时间决定检查，条件决定合入。不得每隔一段时间全合，也不得默认等整个 Issue 做完。

安全拆分优先：兼容基础 A1 可先合；消费者 B1 等 A1；启用 A2 等 B1 和实际组合验收；无关 A3 按自身条件合入。中间每个目标版本都应保持可用。开关关闭不自动证明导入、复用或配置无影响。

确实不可拆分时，先考虑调整实现边界；仍无法安全拆分，选择最小集成候选，经独立检查和组合验证后通过一个主干更新交付。两次快速顺序合并不是原子事务。集成分支可选，只含必要代码，不把作者整个未完分支带进来。

## 09｜接收队列与触发边界

默认优先严重主干问题、已验证成果收尾与明确退回项；必要上游可提升，不让被阻塞下游反过来堵住上游。其余按已批准优先级、等待与成本。插队记录简短原因，不打断长验证。初始实质接收席位 2 可调整；等待不占席位，同目标一个推进过程。

秘书可转交用户的队列偏好，接收者判断技术条件，后台负责执行排序与限流。昂贵验证可以合并已就绪候选批量检查，但不因此合并未经独立接受的范围。秘书离线或没有新事件，队列仍依既有条件运行。轮询、重启、回执重复不制造新任务。

## 10｜候选与证据

固定候选保存 repo/PR/head H/实际目标 ref/观测 base B/merge base/可选受测树 T/采用范围 S/共同交付及接收安排版本/政策与提示版本/本轮实际材料。代码来自固定 Git 对象；Issue／PR body／决定保存实际读取的快照及来源时间。不把 H1 标签配 H2 diff。

证据包含候选／产物、工具版本、实际材料和样本范围、命令或人工步骤、环境、预期与实际、适用退出码、原始输出、验证者与独立性、限制及副作用。运行成功、比较完整、业务正确分别判断。缺材料、漏样本、工具失败不算无变化；“已读”和测试数不证明交付。

原审核保留完整候选和覆盖。当前接收核对 base／环境／范围／新反例与安排增量，记录复用什么、补查什么；原证据可复用，PASS 不自动复制。patch 哈希和依赖清单只作线索。临近接收／合入集中处理增量，不每次主干推进立即重开全部审核。

## 11｜已有工具、临时组合与 PR 记录

复用项目既有测试／对照入口，不重造业务准备器。旧成功不是标准答案；比较内容、身份、来源、状态和副作用。成功变拒绝可能纠错，新增成功可能遗漏材料。昂贵检查按风险抽样或复用须保留覆盖限制；新付费调用单独授权。

在隔离现场以固定 B/H 计算组合 T。Git merge-tree 可写对象库，不修改作者分支、工作区或 index；冲突交负责人，不自动 rebase/cherry-pick/push。仅 read-tree 得到的目录不一定等于 HEAD；测试读取 Git 身份时建立正确候选或限制证明范围。测试不携带发布凭据。

作者维护 PR 叙事和 Review/Fix Record。机器结果优先通过 check run 与固定详情，不与作者争写正文。结果仍绑定完整候选，挂 head 不足。W1 输出发布无关的包；W3 核验实际发布权，可明确选择 status+详情或保留待发布包，不暗中增加权限／双写同义状态。

## 12｜授权、秘书边界与资源

只读／影子：读事实和生成建议；逐次：本次具体获准动作；有限委托：有效来源、角色、repo/target、动作、范围、门槛、上限、时效／撤销匹配后接续。没有委托不新增，已有委托不逐 PR 重批。秘书没有技术判断和合并权限，即使用户说“替我都合了”，也只能联系接收者并呈现需要有效授权的部分。

本人可在同序确认，保存可信原始来源及可恢复正式记录；机器人转录不能自证授权。GitHub approval 可选，须核作者不能自批与目标／范围／方法语义，不强制跳出 UI。共享个人账号的文字不证明本人意图。

首版防误操作、漏步骤和顺手越权，不承诺抵抗同权限恶意进程。后端校验角色能力，不能只写 prompt。秘书不配任意 shell、业务文件写入、测试、review/accept/merge 工具。执行与测试不携带人的确认或发布凭据；核查 gh、环境、credential helper、SSH agent 等常规路径；缺机器人凭据明确失败不回退个人身份。选定原生模式不能落实秘书工具边界，则该模式不开放，不能口头称秘书受限。

原项目账本唯一管理额度／预留／认领与未知；平台不复制余额。任务已授权、具备凭据、调用成功分开；未知机会不自动恢复。发布端只接受登记过的限定请求，不做任意 URL 或 shell 代理。

## 13｜合并请求与恢复

后台在发送前核对当前 H/目标/S/共同安排、开放问题、检查、接收结论、GitHub 条件与授权，用接口支持的 head 条件。不承诺本地重读能原子锁住任意 base/目标，不一次确认带入其他未授权任务。

请求受理、队列中、实际合入分别显示。读回真实提交、目标和树，与受测组合比较；不符／缺失保留“已合入、证据待核”，暂停依赖这些证据的推进，不自动回滚或重复合并。补实际对象证据可恢复；错误目标不能靠测试追认。迟到历史回执不得倒退新状态。

原生 merge queue 需核账户、仓库、规则和 merge_group CI；个人仓库不以它为前置，不为使用它迁移或购买套餐。测试集成成功不等于用户功能已启用、采纳或部署。

## 14｜状态、单写与未知

运行、审核判断、交付、共同用户目标分别记录。交付状态：开发中→待接收→接收中→待修正／补证据或条件齐备→请求中／未知→已合入指定目标。每项有下一步责任、动作、对象和退出依据。关闭线程、Ready、CI 绿不自动消除待复核阻断；全部子 PR 合入不自动关闭共同目标。

副作用先落库再请求，不承诺跨数据库和 GitHub exactly-once；重复去重，未知查原对象。工作项范围、规范化机器／工作区、源分支发布与目标推进分别保护，后端事务而非按钮。心跳消失、租期到期或主进程退出不证明后台写入已经结束。交接核对原 Run、未提交现场、后台命令和远端结果后进行，不强抢、不启动替身。

读取缺页保留缺口，远端成功本地中断恢复原记录，旧审核晚到归档，原生批准保留。秘书退出不取消队列；浏览器刷新不改变真实任务。

## 15｜消息与产物的实际证明

消息有待投递、发送、送达、暂存、拒绝、未知、回复。发送者由连接绑定，角色解析成当前准确会话；已经发送或未知消息固定原收件人，负责人换会话不得偷偷重投。原消息和 Operation 由同一回执一致恢复。

产物登记→匹配版本已读→实际消费入口已验证。送达不算消费，读到路径不算行为验证，新版本重新核对。单机固定包及可访问 GitHub 引用够用；不可访问私有路径明确缺口。正式意见引用原始记录，不由秘书再次摘要取代。

## 16｜G2 的审核与核实循环

先采用目标有效流程，不因平台新增签字层。参考 coding-workflow@1772cd2c 时：新独立 Codex 正式审核；有需核实问题时新 Codex 查事实／复现，独立 Claude Code 查影响／最小修复；Codex 综合；已有范围内修复授权可复用，否则综合后确认；实际移交写权后在验证会话修复；新独立上下文再审。

独立性核对作者聊天、自动记忆与隐藏状态，不只是改线程名；保留必要政策。格式有效只证明结构。只处理匹配 Run 的顶层最终结果，不用中间 PASS／子代理文字触发副作用。错误 finding 提供反证重审同 H，不制造空提交。

证据讨论最多三轮；返工只计实际执行并发布的修复批次，超过三次交网页 GPT 简化反思，不无限开任务。格式、配额或网络停止保留恢复点，不自动改计费。秘书跟进，不加入技术投票。

## 17｜会话、派发与工具

同工具新会话、另一工具新会话、并入负责人待办；并入允许后续顺序 Run，不新建竞争写者。新任务先通过相关共享协调，开始实施时再次核范围／责任与占用；调查授权不自动升级成写入。

能力是已验证版本操作与本次身份／状态的交集，创建成功不推出恢复／暂停／投递可用。准确 session/turn 必须存在，不用最近会话定位。错误 turn 不把 steer 失败变成新轮次。旧长期会话先关联观察，不迁移／重启或夺取控制。原生不可见子代理如实标内部管理。

秘书默认 Codex App Server；接收默认独立 Claude Code 程序化 CLI；具体参数按实际安装与官方文档核验。复用原生工具，不假定本机运行 CLI 等于本地模型或免费额度。后台启动／结果读取与运行中投递分别实测。

## 18｜最终界面

新增工作秘书为首页主入口，保留原三个工作区。秘书对话旁显示跟进清单、待决、成果和来源时间。每个“已做”能打开原操作；未知或未接入明显标注。

## 22｜必须走通的用户旅程

新任务与在途共享入口相关：秘书找到 A/B，A 说明未提交工作，B 可先调查但冲突写入未放行；双方约定更新 Issue，接收角色核安全顺序；按已授权范围启动。接口变化使相关旧反馈失效，其他工作继续。

X 有两个 Issue、三个 PR：A1 兼容先合，B1 只等 A1 不等整个 A，A2 等 B1 与组合验证。另一个独立 PR 不被 X 拖住。无法安全拆分时最小集成一次进入目标，不能模拟两次快速合并等价。X2 新需求不暗中扩大 X1。

秘书离线后 A/B 消息、既有授权执行与接收继续；换秘书读取未完跟进而非重派。秘书被请求写代码／运行测试／批准合并时后端拒绝，即使 prompt 被诱导亦不能调用。恢复后汇报关联真实证据。

PR 全合但无用户场景通过时 X 不完成；已合入树不符显示待核并能恢复；Owner 只处理实际范围/费用/权限取舍，不重复决定。
