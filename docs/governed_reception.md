R1 同时包含受治理重新组合测试和新接收。先接准确候选已知的新接收入口：配置本人来源后，已有 `requireReceiverEntry`／数据库约束目前一律拒绝新接收，尚未消费实际 receive 授权。本增量沿原 queue/operation/Authority/Resource 连接，随后继续新组合自己的 test 授权；不把这一步称为全部 R1 完成。

输入为固定接收计划、准确 item/packet/H/B/组合身份、已保留的一次确认或委托 reservation、同原操作的资源请求。来源、授权有效期／撤销、范围、停止及资源状态在准备与实际发送前重核。模型报告、浏览器钥匙或实现者权限不能作为接收许可；一次确认不能被另一操作或不同计划复用。原结构化输入和角色工具范围不扩大。

新接收按原 operation 开始并登记实际发送、原版本／会话、完整终态与判断。结束后据真实捕获报告原资源结果；资源回执未知只查原请求，不新认领、不自动退款。中断、部分输出和无效最终判断保留原状态；历史结束结果在授权后来失效后仍可读取。旧客户端新开／已打开的未绑定入口不能绕过新增门，且保留已有受治理修复能力。

验收采用实际本地受控 CLI 夹具和原资源协议夹具：准确授权一次接收／重复0，缺授权／错误动作／旧材料／跨操作资源／撤销／停止均拒绝新增输入，实际启动前变化、结果后资源回执丢失及原结果恢复。必要独立复核另绑定固定H；无须为故障样例消耗真实模型额度。后续真实原生验证只在既有订阅、工具与用量条件满足时沿明确原请求执行。

不合并、不自批、不改治理、不新增费用或迁移认证。原全部52要求和R1其余重组测试、远端候选／通知、责任接续与完整用户旅程继续，检查点不代表停止。

## 当前消费契约

既有 `tongxu-queue-receiver` 计划新增可选 `governance`，包含已 reservation 的 `authorityIntent` 和同一原 operation 的 `resourceRequests` 数组。没有本人配置的旧入口保持原行为，不能偷偷忽略传入的 governance；已配置本人来源的新接收必须提供准确绑定。原已结束报告可继续回读，不因事后撤销而抹去。

同一原队列先完成影子检查，仍未进入 receiver 时准备资源请求。程序在原 events/blobs 登记准确计划、原 packet、授权动作摘要及资源集合，然后查回／认领原资源，确认 held 后才 reserveReceiver。仅声明“有权限”或存在资源记录不够。即使资源集合为空，同一 intent 也只能绑定一个原 operation／计划。此入口接受 background 或 receiver 的 receive 动作；实现、测试、协调权限不能替代它。

实际启动前重新核原本人来源、撤销／停止、来源材料与原资源。`runClaude` 的受治理启动回调把实际进程创建和首次输入提交放在同一同步事务内；最后一个队列检查不能在进程启动前先释放事务。新 SQL 准入与原 format20/21 的资源准入共用一次准确记录，旧已打开客户端不能跳过绑定；受治理修复原守卫仍保留。

完整捕获结束后，控制器返回事实先写回，再返回当前接收状态并报告原资源结果。无效但完整的最终判断按失败结果结算；中断或不完整输出保留未知及原资源，不当作成功或自动退款。发送前资源回执丢失只 lookup 原请求；终态后资源结算回执丢失也查原请求，原模型输入不重发。

当前核实使用真实本地子进程与原资源协议夹具，角色输出／本人／账本均明确为隔离样例，0官方模型。作者首次检查发现返回对象仍带控制器返回前的旧字段，已改为回读持久状态；原失败保留。独立源码复核另绑定准确H。当前未接新组合 test 的输入授权、test资源结果与后继新integration intent，也不新增真实Owner身份或生产配置。

作者验证已包含：原许可与资源仅消费一次、事后撤销仍可读原结束报告、零资源计划的唯一绑定、实际输入写入期间第二数据库连接不能取得写事务、发送前停止、未配／错误动作／过期材料拒绝、失去认领或结算回执后的原请求查回、无效完整判断与不完整结果分别保留、已打开旧接收／资源客户端被SQL守卫拒绝、format21原守卫组合，以及启用新接收后真实隔离工程修复仍可修改／测试／再审并结算。相关旧接收、授权、资源与纠正回归通过。上述角色、Owner和账本均是明确夹具，不转成真实身份或业务接受。
