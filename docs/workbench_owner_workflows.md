# 本人停止后的恢复

“委托与停止”页面可以为新增实施、新增投入、新合入分别准备本人停止或恢复请求。它复用原权限记录及原来源核对；保存请求不会改变控制状态，查看密钥不能代替本人确认。成果决定“停止后续投入”形成的停止也可从这里恢复。

准备请求绑定当时所选控制项的修订，采用前在原事务内再次核对。其他操作已改变该控制项时，旧请求保留但不能覆盖新状态；重复采用已经成立的决定只返回原记录。第二次停止、恢复形成新的准确请求。恢复一项不清除其他停止、撤销或未知运行，不重新派发原任务。

`owner-control-journey.test.ts` 在同一原队列、同一工作台内验证成果停止、本机恢复拒绝、独立原来源恢复、其他停止与撤销保留、重复和冲突请求。这里的来源是明确测试夹具；不代表真实本人已采用目标或生产成果。

## 秘书读取同一入口的本人记录与复盘

新的秘书计划可显式选择 `workbench: {path, sha256, source}`，固定同一启动配置中的一个任务。新增查询复用 `OwnerControls.state`、`OverallControls.state/report`，读取准确目标正文、委托、撤销、三项停止、复盘状态与完整原文。可见任务、原队列和复盘选择须匹配；未选任务、换文件和报告中的新动作不能扩大访问。秘书仍不能准备或采用本人决定、恢复控制或启动复盘。

未配置此选择的旧秘书计划保留原工具集合。已完成的旧查询从原捕获查回，不因后来页面配置变化而重新发模型。新增配置、实际调用、工具响应、观察引用和完整最终答案均进入原捕获与重放核对。组件数据来自各自原读取事务，不宣称跨读取或跨队列原子快照。

作者验证包括页面与秘书目标/控制投影一致、实际进程夹具读取同一复盘全文、独立候选与缺少接受基线保留、越界/新权限查询拒绝、完整捕获重放零新增调用。普通来源确认仍由独立本人完成；这不是完整五项本人控制、组织派发或真实日常流程的验收声明。

## 组织安排由原任务待办消费

组织安排登记之后，原开发任务的下一条未准备待办会在原事务内附上准确的当前协调材料，并保持原任务、原负责人、原请求及原执行器。任务上下文和协调上下文都列入必须消费的材料。已经准备的旧输入不重写；新安排、不同负责人、多个歧义安排或移除后的旧任务不能靠更换入口绕过原限制。

普通工作台联系、原任务 worker 和原 A→B→A 联系消费者在完整原回复返回后，将结构化反馈、调查产物及确实读取的前置记回原 CoordinationRecords。固定输入缺少后来产物时，对应阶段继续等待，不能据摘要猜测消费；部分回答和格式无效的报告不生成技术前置或写权。报告本身仍保留供核对。

`organization-owner-journey.test.ts` 使用同一个 HTTP 工作台登记安排、联系原 A/B、消费准确 A 调查报告，并核对阶段从等待变为技术前置满足。写入授权始终独立。重复不发新输入；安排变化和负责人变化拒绝旧/错输入。这补上原普通联系消费者的连接，未把所有协调 CLI、自动修复、目标换版或完整用户旅程统称通过。

首页现在优先呈现所选范围的原目标、非目标、停止项和成果决定，然后才显示任务/报告数量。只有目标采用与控制观察完全一致的来源才合并展示；同名范围有不同记录时分别保留，不把一个来源当全部来源。旧任务范围与新采用不一致、示例来源、场景待核和历史成果仍明确显示。此投影不增加本人决定、自动迁移或新的执行入口。

秘书复盘查询只呈现原持久状态，不转发查询对象自身的 `active/currentControllerProblem` 临时字段；另明确返回 `controllerActivity=not_observed`。查询进程空闲不能证明原页面控制器或原模型已结束。
