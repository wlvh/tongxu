# 本人组织方式与按需复盘的工作台连接

继续原 #9 的五个入口与 #2/#5 的工程收敛，沿用 PR61 的 b8e2cab 前置；不新建调度账本或常驻审核角色。目标/委托、停止和成果入口已有原消费者，本段连接剩余组织方式与复盘，随后验证完整使用流程。当前52项要求及历史证据保留。

组织方式针对明确选择的已有任务，提供固定的并行、按阶段串行和统一负责人安排。页面呈现任务、准确前置、共享部分和拟定负责人，操作登记到原 CoordinationRecords。登记安排与取得写入责任分开：未知/活跃原执行、原租用和受管交接仍由既有消费者检查；新的安排不能自行释放旧写者。默认继续原A，只有明确选择的统一负责人选项才提出角色变化。

可信启动配置固定候选任务和安排内容；页面只选择方案及所见的上一修订，不接受任意命令、文件路径或模型拼出的权限。新技术修订保存准确 previous，竞争或过时界面不得覆盖后来安排。已有 Owner 来源时只使用原有效委托，并把准确安排摘要绑定到原 coordinate 动作；无来源的本机影子配置只登记操作者安排，不自称本人采用或写权。刷新只读，已有结果不因为查看而重发。

复盘仍使用原整体审核模式和四类材料：上一接受基线、累计变化、当前行为、当前文档。准备、实际模型派发、原结果恢复和全文读取分别呈现；未知或缺少采用基线不能形成“没有整体漂移”的结论。新增页面消费者必须落实原停止、授权和资源边界，不借查看钥匙绕过它们。简化反思和整体复盘不混成同一条成功记录。

启动配置的 `organization` 指定固定目录文件及其 SHA256；每组选择同一原队列的2至8个已选任务，方案使用已有 CoordinationPlan。HTTP只接受所选方案标识和所见上一修订。完全重复读取原登记；刷新后重选相同内容且材料仍适用时不制造空修订。同一任务材料变化时，必须允许重新选择原方案并登记准确新修订，以绑定新证据；旧安排继续保留。页面展示当前阶段仍缺的共享反馈及准确产物。已有本人来源时逐任务绑定原有效协调委托，未配置来源时仅表示本机固定安排；两者均没有启动模型、产生新写权或替本人采纳。

复盘配置 `overallReviews` 选择已有接收操作及固定 OverallPlan。页面不接收运行时命令、路径或替换材料；四类材料的名称与摘要可见。准备、派发、原结果查回、核清未启动记录和完整报告共用原 `overallReview`、ReviewRecords、执行器与捕获。关闭服务等待其已拥有的操作返回；刷新与重开不会新派任务。过时或未知输入保留，完整报告缺失时不报完成；无基线始终保留 `noOverallDriftEstablished=false`。

启用本人来源的队列必须有本次复盘的准确协调授权；已有资源配置必须绑定原请求。发送前重新核原来源、停止、候选、占用和资源，原始派发先登记。旧消费者仍被持久保护拒绝；有界启用此消费者与原发布保护组合，未删除原保护。完整结果只向原账本回报实际结果；丢失结算回执先 lookup，不能重发模型或推断退款。已有未治理捕获可读与原路径恢复，新增治理计划不能套用它的授权。
