# 项目秘书对话

选择GitHub仓库后进入“工作秘书”，直接输入并发送问题。它不依赖旧任务秘书模板，也不要求先登记开发任务。可以在同一对话中追问、查看全文和来源记录，或新开一段对话。历史按GitHub账号与仓库数值ID保存，换项目不会带入其他项目的问答。

秘书能读取当前项目的资料、Issues/PR列表与完整正文，以及该项目已关联任务的原状态和完整接收报告。它可以解释记录、梳理待办和帮助澄清目标；当前对话没有写代码、执行测试、创建开发任务、发布、批准或合并工具。模型获得的材料和回答都作为数据处理。

## 对话与原件

每次发送先在一个事务内登记准确问题、对话与上一个消息，再由原受限Codex执行器调用模型。同一requestId的重复进入只读取原登记，不能替换问题或重复发送。每个项目同时只开始一轮问答，其他输入等待其结束。网页只提供问题、请求ID、对话ID与前一消息；执行程序、存储位置、权限和工具来自本机固定配置。

追问传入该对话此前保存的完整问题和回答。每条新消息使用新的原生上下文，记录准确会话/轮次，**不冒称接回同一原生会话**。单段历史最多64个问题，完整上下文超过192KiB时要求显式新开对话；原全文保留，不自动截断或总结替代。查看旧答案会核对原始捕获及来源引用，不重新调用模型。

模型使用现有ChatGPT订阅。原执行器在实际发送前读取当前账号与订阅内限额，并拒绝API计费覆盖和不可确认的普通用量；没有重写旧秘书模板中已过期的用量日期。模型和工具版本按实际能力准入，每次运行记录真实身份。输入、原始事件、最终回答、来源观察和失败记录保存在配置的私有对话目录。

## 停止与恢复

“停止本轮”只控制当前入口拥有的准确轮次，通过原生中断请求和进程收尾保存原件；停止回执与完整终态分开记录。即使GitHub暂时不可用，已有受管请求的停止仍可使用，不因此授予新输入权限。关闭入口会停止本入口的问答并收尾，不新增后台模型循环。

刷新、换项目和重新打开只读取原记录。注册后中断、部分输出、失败或未知捕获不会记作完整回答，也不会自动重发。原执行者仍活动或状态未知时，保留等待；确认它结束后仍没有完整回答，则显示未完成历史。用户可明确发起后续问题，旧请求本身仍不被重跑。

## 本机连接

安装器在原WorkbenchPlan中配置`projectSecretary`，包括私有记录目录、现有Codex入口、受限配置和超时。正常使用不需要用户拼JSON。GitHub来源仍通过原只读项目服务，原任务仍通过原QueueStore读者，没有复制任务队列。旧任务秘书的完整历史回答保留在页面的“原任务秘书历史”。

协议使用明确的`project-conversation`来源类型，绑定账号、仓库、对话和初始来源摘要，不伪装成PR或已登记开发任务。仓库没有提交时，提交和分支字段为空，不捏造H/B。

验证需分别记录测试程序响应和真实模型问答，覆盖直接发送、两轮全文上下文、跨项目拒绝、重复与冷重开、额度失败、部分回答、停止及原件损坏。真实试用只能证明实际执行过的范围，不代替本人接受或权限批准。
