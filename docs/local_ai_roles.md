# 本机 AI 与角色设置

正常启动并选择 GitHub 仓库，打开“AI 与角色设置”，点击“检测本机 AI”。页面列出已有 Codex CLI、Claude Code CLI、Kimi Code CLI、Gemini CLI、OpenCode 的入口、版本、认证状态，以及它们实际返回的模型和推理选项。未安装的新增程序单独显示，不把未找到入口当作检测成功。不会安装程序、登录新账号、复制凭据、改变额外用量开关或发送模型问题。其他尚未实现协议适配的程序不会被冒称可用。

为工作秘书、任务负责人、独立审核、事实核实与修复、影响核实、接收与综合分别选择调用程序、模型、推理强度并保存。“调用程序”是本机 Codex CLI 或 Claude Code CLI 的安装入口，同一程序的不同路径分别显示。选择按当前 GitHub 账号和仓库数值 ID 保存，名称来自 CLI 目录，不固定发布版本。选择“使用程序默认”时不覆盖该参数，也不把不同程序的强度当成相同能力。

“使用默认配置”清除该项目、该角色的单独选择。项目秘书回到本机启动配置的程序，卡片显示最近一次程序检测回报的模型、强度、时间及来源；未回报的值明确待核，不从模型目录猜成当前配置。任务负责人等角色使用各自任务的已有执行计划，尚未指定具体任务时说明“由具体任务决定”，不能展示一个虚构的统一默认值。默认值可随程序配置变化，检测记录不等于随后一次运行的实际参数。新 Codex 运行不再暗中覆盖为 high；旧捕获中的 high 原样读取，原生续接按原轮次实际提交/响应保留模型和强度。

Codex 使用官方 [`model/list`](https://learn.chatgpt.com/docs/app-server#list-models-modellist) 的模型及 `supportedReasoningEfforts`；Claude 使用官方初始化结果中的 [`ModelInfo`](https://code.claude.com/docs/en/agent-sdk/typescript#modelinfo) 和 `supportedEffortLevels`。本机实际目录而非网页中的示例决定可选项。Claude 的 `sonnet` 等名称跟随其工具当前映射，页面同时显示当次解析的具体模型。运行前再次核对可用性，不因旧目录中存在就假定今天仍可运行。

同序对不同执行协议的接入程度也会影响可选组合。当前项目秘书和受控修复使用已接入的 Codex 受限工具接口，Claude 的同等工具接口尚未接入，因此页面将该组合标成不可选；这不表示 Claude 本身没有工具能力。任务负责人的只读联系和材料综合支持两个入口。既有正式审核、修复和影响核实流程还有自己的捕获协议；页面仅开放已接入该接口的组合，运行时也再次检查。不支持的跨执行器组合会明确暂停该动作，不静默退回另一程序、删除工具或降低权限。

## 设置怎样进入实际执行

- 秘书每条新问题在原登记流程中保存本次选择，再向 Codex 的线程与轮次提交模型、强度。执行器返回的实际模型或强度不符时，先于问题发送拒绝继续。全文回答的读回会同时验证原目录、原请求参数和实际响应。
- 原任务负责人第一次准备新的运行计划时，原请求保持不变，所选执行器及参数固定到派生计划，并保存来源记录。已准备计划和原生会话恢复直接复用原记录，不采用之后的新设置。带明确模型选择的原生控制与续接，也核对原目录请求和原模型；保留相同选择可以续接，换成其他选择则拒绝。选择另一个程序不授予写入、发布或接管权限；原执行未知或未结束仍然阻断。
- 新的审核、事实核实、影响核实循环在原输入封存时保存选择，后续阶段使用同一份记录。接收综合的消息计划和独立整体审核同样保留选择。已有冻结的老计划不追溯改写。旧任务秘书模板继续使用它自己的原条件；正常项目秘书使用新设置。
- 实际命令、模型目录、运行身份、线程、轮次、完整报告和失败原件分别保存。Claude 的运行初始化在输入发送后才确认实际模型；若不符，该原请求保留为已发/未知，拒绝消费结果和自动重发。Claude 强度记录的是目录支持及实际命令参数；没有独立返回的有效强度时明确标为未观测，不冒称已经证明模型内部计算量。模型名称出现在下拉框或进程退出成功，均不能代替完整结果及参数核验。

## 升级、失败与恢复

CLI 按当前稳定入口解析，并按操作所需能力检查，不比较发布版本白名单。Claude 桌面安装的版本目录按当前已安装入口重新解析；不会让一次检测到的旧目录成为长期门槛。单次运行中的程序变化仍会保留未核状态，不能自动重发。

未知模型、错误强度、认证失败、计费覆盖或所需工具缺失，会说明具体原因。本机显示已登录不证明服务端仍接受令牌；真实请求若返回认证错误，会及时显示原因，不再等一个不会出现的成功终态。对单条输入、进程已结束、完整原件证明工具/子任务为零且 CLI 明确报告零用量的 401 取消，可追加“已中断”的核验，显式结束原失败请求后再处理新问题；旧记录和旧错误不改写，不自动重发。其他含糊失败仍保持待核。一个角色不可用不妨碍读取旧报告或使用其他角色。多个页面同时编辑时，未编辑的卡片刷新为最新值，已编辑草稿保留原版本并提示冲突，不将旧草稿悄悄套上新版本覆盖他人选择。保存设置和重新检测都不会启动模型；只有原流程的明确运行操作才可能发送新输入。原报告是证据，不能修改 AI 配置、权限或下一轮命令。

本机记录目录由安装计划的 `aiSettings` 指定。配置记录复用原任务与操作来消费，没有另建任务队列、调度器或通用迁移系统。准确当前余项仍是本机原 `completion-coverage.json.currentRemainder` 的 F09.localAISelection；本人采用与完整产品验收另记。

## 从入口核对实际调用

“AI 与角色设置”中的每个角色同时提供使用入口、具体交互方式和角色提示词全文。提示词查看展示公共边界、角色与固定上游政策；每次执行附加的任务政策、材料、工具和输出要求仍以该次原运行记录为准，不能用当前模板覆盖历史输入。公共政策已嵌入系统提示，不要求模型再打开一个未注册读取工具的 `runtime_contract.md`。正常启动的固定文件清单也包括全部提示词；提示文件变化时先拒绝启动，不能仍显示原受测版本。

| 用到 AI 的地方 | 用户入口或实际触发 | 程序怎样交付项目材料与收回结果 | 工具与提示边界 |
| --- | --- | --- | --- |
| 项目工作秘书 | 常驻右侧的工作秘书，直接输入和发送；收起后从右下角展开，没有已登记任务也可用 | `ProjectChat` → `BoundedCodexSession`；5种原项目查询加完整协作消息读取，返回全文与来源 | `secretary` 完整政策 + `projectChatInstructions` + 实际动态工具；只读，不能把聊天当成开发派发 |
| 原任务秘书及获准跟进 | 右侧“原任务历史与跟进”的既有问题/动作 | `SecretaryControls` → `runSecretary`；使用该任务已固定的查询、报告、联系或提醒工具 | `selectedSecretaryTools` 只开放已登记动作；旧模板仍用其原执行配置及条件 |
| 原任务负责人、联系、补查和综合 | 任务与报告中的原联系入口；目标/范围页中已准备的补查 | `TaskControls` / `ScopeFollowupControls` → `TaskInbox` → `runMessages`；完整材料与前序报告随原请求送达，完整消息可读回 | `issue_owner` + 完整上游 + `messagePolicy`；当前联系无任意工具，报告不能自行创建新权限 |
| 事实核实、受控修复 | 原任务 RETURN 处理；CLI 受控修复入口 | `ReturnControls` → 独立 worker → `runQueueRepair` → `runRepair`；读取限定文件、运行登记测试，写权成立后替换允许路径，再取得新候选 | `verifier_fact` + 固定任务政策 + 受限工具；worker 显式接收已校验的角色选择，原操作冻结后不受后续设置影响 |
| 独立候选审核和再审 | 修复链自动进入新审核；原 relay CLI | `runCodex` 或无工具的 `BoundedCodexSession`；当前候选源码、差异、测试和原报告作为材料输入 | `reviewer` + 完整固定上游审核政策；独立上下文，无写入，无工具时不能声称重跑测试 |
| 独立影响核实 | 原核实/修复链在事实阶段后触发 | `runClaude` 收到固定材料、事实报告，原始最终全文再交事实角色综合 | `verifier_impact` + 工作流与任务政策；无工具，不按报告中的命令另行执行 |
| 技术 PR 接收、组合接收、反证后的重新接收 | 既有接收 CLI，或已有退回/反证流程的后续阶段 | `runReception` / `runPairedReception` / `runMemberRefutation` 装配准确源码及原证据，Claude 返回绑定候选的完整判断 | `receiver` + 工作流 + 接收输入契约；使用接收计划的原配置，不是设置页“接收与综合”的成果验收角色；没有通用项目聊天启动入口 |
| 按需整体复盘 | 判断与复盘中的已登记复盘方案 | `OverallControls` → `overallReview`，输入已接受基线、累计变化、当前行为与文档 | `reviewer` 独立模式，当前选择固定入原输入；基线不足明确等待，不把空页或提示词当成执行 |
| 成果场景验收与解释 | 成果与验收中的已登记验证方案 | 原场景执行器先提供实际输出，`runDeliveryAssessment` → `runMessages` → 原成果记录消费完整判断 | `acceptance` + 场景契约；不代替本人接受，也不把读报告说成亲自执行工具 |
| 多任务只读协调 | 已固定协调计划的 CLI；页面组织方式保存本身不发模型 | `runCoordination` → 原消息执行器，按具体前置传入已完成产物 | `issue_owner` / 指定联系角色及 `messagePolicy`；当前组织设置不是通用自动调度 |
| 子任务实现者、网页外部解读/简化反思 | 目前保留角色政策、原会话关联或外部结果记录 | `implementer` / `external_report` 模板的存在不等于本机新增独立启动器 | 不宣称本轮已接通独立子任务 Agent 或网页 GPT 自动调用；已有修复实现由上面的受控事实角色承担 |

新项目只有仓库资料并不自动具备已授权 RETURN、接收或验收计划。相应页面须解释缺少的原任务/方案，不能因为保存了角色设置就显示运行成功；用户也不应为了读取现有报告而手工搬文件。项目秘书现在复用任务页的完整消息读取器，按所选项目、任务、run 与 messageId 读取原件；越界或原件不完整时不提供成功结论。

本轮定向验证分别检查真实子进程的设置传递、修复执行器消费所选模型与真实本地测试、原报告全文与越界拒绝、所有角色的完整提示组装，以及正常页面入口。模拟 CLI 结果标为测试样例；真实模型调用和历史证据单独记录在唯一当前余项引用的本批交付中。Claude 认证或 Docker 环境不可用时只暂停对应真实验证，不用样例补造通过。


## Kimi、Gemini 与 OpenCode

三种新增程序通过 ACP（程序之间传送会话、问题、配置和结果的协议）接到原任务消息流程，首批支持“任务负责人”和“接收与综合”的无工具材料处理。角色提示和准确材料仍来自原任务，原队列负责发送记录、全文回读和防重复；未新增任务中心，也不把文件生成或进程退出当成模型完成。需要专用文件/测试工具、正式审核捕获或原生补充/续接控制的角色暂不开放这些组合，原控制要求不会被静默删除。

模型及推理选项来自实际 ACP 会话目录；每次准备和执行重新核查所选条目。`on`、`max`、`future-depth` 等值由程序实际声明，不互相换算；没有回报强度时只提供程序默认。ACP请求编号单独标为传输引用，不捏造程序未提供的原生turn ID。

Kimi使用现有官方托管OAuth入口，拒绝API覆盖和无法隔离的启动扩展。每个独立工作区的主角色配置为空工具/空子代理；发送前后读取该准确会话的原生profile.bind，核对提示和实际工具列表。Gemini使用独立系统配置及拒绝全部工具的策略，关闭MCP、扩展、技能与hooks；OpenCode使用纯净模式、独立无工具角色和拒绝权限。所有反向文件、终端和权限请求均拒绝，出现工具事件不能消费为成功结果。未知配置或所需接口缺失只暂停相应入口，不切换程序。

本机检测不登录、安装、提取/复制凭据或发模型问题。执行仍依赖原任务的费用证明、现有账号和授权。Kimi存在独立Extra usage/Booster机制，不能把Claude的关闭确认自动套用到Kimi；新增真实模型验证须先确认相应费用边界。OpenCode只接收已有OAuth连接的模型，API key或外部计费路线不在本次授权内。未安装程序的结果仅为协议测试，不能写成真实模型运行成功。

官方接口与实现依据：[Kimi ACP](https://moonshotai.github.io/kimi-code/en/reference/kimi-acp.html)、[Gemini ACP](https://geminicli.com/docs/cli/acp-mode/)、[OpenCode ACP](https://opencode.ai/docs/acp/)。源码快照、实际本机元数据及受限边界核对在唯一当前余项F09.localAISelection.additionalCLIs引用的本机证据目录保留。
