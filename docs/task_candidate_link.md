# 同一任务形成真实 PR 后的关联

本增量对应 Issue #8 NT07–NT10，接续 #41 的任务接入。开发任务已有稳定身份和原负责人待办；形成候选后，用准确关联把原任务与既有 W1/W2 材料连接起来。原开发任务包和 PR 候选包分别保留，关联不改写任一包。

## 关联核对什么

`task link` 重新读取原任务定义中的实际工作区，核对仓库、H、B、target 与范围来源，再绑定原队列中的准确候选 item/packet/fingerprint。候选必须是单个真实 PR 的原材料，不能拿另一个开发任务或组合锚点冒充。候选过期、来源损坏或身份不符时拒绝关联。

选定文件要同时满足：工作文件原始字节与 HEAD 一致；Git 索引只包含与 HEAD 相同的 stage-0 条目；Git 跟踪的文件所有者执行位与 HEAD 匹配（不能拿 group/other 的 x 位代替，也不把它解释为 ACL 或运行环境的执行许可）。程序只用对象读取和 `ls-files --stage -z` 读取索引，不调用可能触发仓库 clean/process 过滤器的工作树 status/diff。原 TaskObservation 仍明确不观察索引；新增 TaskLinkSource 独立记录本次索引/权限核对，不改旧观察的语义。

只核声明的文件，不声明整个仓库干净。读取期间发现文件、HEAD、分支、索引或权限变化时保留拒绝。源码内容沿用严格 UTF-8、保留 BOM、拒绝链接的原实现。

## 延续原身份与报告

关联追加到原 events/blobs。任务 id、定义、旧材料包、负责人、输入、完整报告、未知发送和失败记录不删除或改名。相同关联重复提交不再创建记录。

关联后的负责人请求自动取得准确关联、W1 采集清单与 W2 验证记录；原始工具输出和采集正文仍由原消费者按引用读取，不声称本联系消息包含所有原件。完整输入的消费仍由原消息执行器核对。候选的测试/材料缺口会随记录提供，关联不把它们改成通过；缺少执行前置也不妨碍如实登记关系，但原执行消费者仍会等待。

派发前重新读取所涉及任务的文件、索引与权限，并检查已装配关联的当前性。PR 新 H、材料包变化、未提交内容、暂存区或权限变化都会阻止旧关联上的新发送。已完成报告保持可读，但如果它消费的关联过期，工作台和秘书将其标为历史；它不会被移植给新候选。

任务内容与关联来源观察在同一事务中登记。较旧的观察不能覆盖较新的观察；同一时间出现不同内容时保留冲突，直到取得时间更晚的新观察。修补前未记录所有者执行位语义的旧关联保留为历史，不追认已完成新检查，需重新观察并显式关联。

有多个仍当前的候选时，程序不会自动挑一个。`resolve --link` 按准确关联返回对应候选；一般负责人装配在歧义解决前等待。解析关联仅提供原候选标识和材料，不转移接收、实施、发布、合并或外部会话控制权限。

## 格式与入口

关联影响派发条件，因此显式启用格式 16。升级要求原队列没有活跃或未知 operation、claim、消息、整体审核或未核实发布。旧客户端必须拒绝新格式；配置 Owner、资源或合并能力不降回旧格式。原格式 15 仍可只运行未使用关联的任务接入。

```sh
node dist/src/task-cli.js enable-links --store /absolute/queue
node dist/src/task-cli.js link --store /absolute/queue --request /absolute/link.json
node dist/src/task-cli.js resolve --store /absolute/queue --task TASK_SHA256 --link LINK_SHA256
node dist/src/task-cli.js status --store /absolute/queue --task TASK_SHA256
```

`link.json` 的字段为：

```json
{
  "schemaVersion": 1,
  "kind": "tongxu-task-candidate-link",
  "task": "原开发任务的 64 位摘要",
  "candidateItem": "已有 W1/W2 候选的原队列 item 摘要",
  "source": "本次关联的实际来源"
}
```

工作台显示当前或历史关联及准确 PR 链接；秘书从相同快照取得同样的状态。普通页面不展示工作区路径、源码或完整工具原件。

## 验证与范围

`tests/w6/task-candidate-link.test.ts` 使用实际 Git、SQLite、子进程和明确的模型/授权/供应方夹具，验证任务身份连续、完整报告保留、原验证记录消费、脏文件/索引/权限、过期候选、历史投影、重复操作、未知责任、格式升级及原授权资源消费者。真实候选材料的 W1/W2 验证另存私人证据，不把夹具模型标为真实模型。

这是准确材料关联和消费者接入，不是通用代码实施、自动接受任务、生产合并或完整 G11/G13。受控实现、五项人工控制、X1/X2 及整体集成继续沿用原前置和授权范围。
