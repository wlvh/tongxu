# 正常工作台中的成果准备与执行

继续原 #9 的正常使用流程。现有成果、验证、领域判断、本人决定和原件回读已经交付，本段把准备和发起连接到同一页面，复用原events/blobs、验证、消息、权限和资源消费者；不另建成果账本或调度平台。

配置已明确选择的本人控制任务，可以在“成果与验收”准备固定成果材料。可选成员仅限这些原任务及其原记录中的明确后续工作；不同队列不混成一个批次。程序读取准确packet、材料摘要、采用范围和目标/非目标，用户填写成果名称、所属Issue及场景预期，不需手写manifest。材料或采用改变时保留草稿并要求重新核对，不能静默换成新版本。

登记沿原DeliveryRecords，重复查回相同批次，修改必须绑定所选前版。旧版本、验证和本人决定继续可查，旧版通过结论不转移。新目标尚未对应当前任务时，先通过已有A后续工作入口继续，不能直接改写旧任务范围。准备只登记材料事实；当前采用来自原持久记录，本次查看没有重新核远端，不授予测试/模型/写入/接受权限。

页面从同一原队列发现完全属于已选成员的成果，再复用原成果决定表单和完整报告。原来显式配置的成果选择继续保持；无本人控制选择的旧只读入口不会增加准备权限。一个来源不可读时显示该来源缺口，其余来源继续读取。

本段还需接原实际验证和独立领域判断的发起：受信配置固定测试/模型能力，页面仅选择准确对象及场景；发送前沿原候选、授权、用量、资源和停止门检查。部分、未知和中断先核原运行，不能换id重派。新准备、实际执行、独立结论和本人接受分别记录。

当前源码开发检查已覆盖新批、前版竞争、重复零执行、新范围准确后续成员、HTTP越界/权限/源变化拒绝和重开查回。尚待准确固定候选的独立复核、页面完整流程和后续验证/判断连接，不据此更改52项原验收状态。

## 原消费者的实际发起

启动配置可显式增加 `deliveryExecutions: {path, sha256}`，该私有文件列出有限的验证/判断能力，并绑定已选本人控制来源。验证能力固定原W1快照、原隔离测试计划和结构化样本；判断能力固定已有CLI、指令来源、工具限制、订阅边界和原资源引用。网页只能选择这些能力、当前批次成员及场景，不提交命令、可执行文件、目录或新的费用权限。

页面准备时在原events/blobs保存准确请求，复用原权限提案；独立判断的完整输入由原DeliveryAssessmentRecords装配。采用目标不自动授权执行。核对准确本人来源或适用委托后，实际执行继续由原DeliveryValidation/DeliveryAssessment、原控制器锁、权限/资源与捕获机制负责；新页面不另判执行终态。原来源/停止、候选、证据和用量在实际边界再核。

同一固定请求换一个页面显示名称仍对应同一原操作。重复、恢复和核清关闭均沿原消费者；未知或部分结果不能通过换ID重派。读取原输出是独立动作，消费未确认时仍保留原文并显示未完成。已准备但尚未登记到验证器的材料不称为已启动验证；完整结果不签本人接受。

作者已通过同一HTTP工作台的实际Docker验证→原件装配→独立进程夹具判断→全文与重复零执行；停止在输入前拒绝，未确认消费的完整原文可查，未知不能换ID。首轮在权限观察目录准备处失败，尚未注册验证或发送模型；修补后原失败保留。真实官方模型、准确新候选独立复核和实际页面流程尚须按范围补证，不将夹具称为真实本人或领域验收。

## 当前复核与原失败

批次准备在ad2的独立审核发现两项P1：同item跨队列的下一版草稿选错来源，以及第65条历史被接受后使新发现入口失效。177分别绑定原来源，并在原登记事务拒绝超限新增；独立复验关闭两项，保留原REWORK。长ID在窄屏换行，不隐藏完整身份。新生产者也遵守原任务成果读取器每成员最多8个当前逻辑批次的容量；已有批次可继续明确修订，原64历史容量不变。

新的执行消费者联合检查曾发现读取期间恰好完成造成“旧阶段+新空闲标志”的混合快照。原数据库已保存完整结果，失败原件保留；现在保留读取开始时的活动状态，使页面继续刷新取得完整终态，原任务控制和后续控制采用相同修补。定向场景在真实执行期间阻挡一次Owner查询，验证不会把旧阶段误报为空闲，未改弱断言。当前相关26项通过，仍须准确候选独立审核及实际浏览器全程核对。
