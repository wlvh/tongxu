# 原资源记录与最后一条未发消息接续

本片段接续 #8 评论6309110044，固定前置为 PR39 a1cbebc，继续使用原 `message-continuation-cli prepare|run`。它只处理一个明确情况：前序消息全部有完整回复、准确材料消费和已核结束捕获，最后一条从未登记发送。原运行、报告、捕获和原资源请求均保留，不把它们改成整链完成。

## 一个原队列内的处理顺序

1. 读取原捕获并核对候选当前性、唯一接续选择和原控制器。准备入口只生成固定材料，不查询或结算供应方。
2. 对已配置原资源的运行，把确已执行的完整前缀登记为 `partial_returned`。原最后一条仍是未发送，`originalRunCompleted=false`。证明绑定原输入、会话、最终原文和捕获；不能从模型报告中取得权限或消费事实。
3. 向原供应方查询原请求，并用 `state=failed` 表达原整链没有完成、前缀已有实际执行。供应方仍决定自己的结算规则；本程序不记新余额、不声称退款或免单。原 outcome 及供应方回执必须对应，才允许下一个消费者进入。
4. 新上下文按原最后一条任务、完整前文和当前准确 coordinate 授权运行。它仍经过停止、候选、角色工具、计费与资源检查。新资源认领和原结算分别登记，不能用旧资源结果代替新投入授权。
5. 只有新消息完整且其资源结算也成立，接续结果才记完成。原链仍未在原会话发出最后一条；工作台显示由哪个新运行补齐，不把原消息改为 Reply。

## 失回执、更新前置和撤销

原结算回复丢失时，重复入口先查原请求，不重新发送模型或重复结算写入。后继认领未知时保留原 run、attempt、计划、授权意图和请求字节；只允许为同一选择追加新的计费观察。旧计费过期不靠修改原计划绕过。

原前缀已经结清，而且后继没有任何资源绑定、模型输入或未核清进程时，可以在原有三次准备上限内显式更新准确授权。原结算证明及首次交接目标保留为历史，新的选择另记；不是删除旧认领或接管未知执行。新的授权仍需来自现行已采用来源。

撤销禁止新输入与新认领，但不阻止对已发生前缀记录事实。原 claim 未确认、原捕获缺失、部分回答、旧控制器活跃、候选变化等情况保持明确等待。纯原件回放不调用资源供应方或执行资源交接。

## 入口与准确边界

继续使用既有请求 `tongxu-complete-unsent-message`，含 `allowNewContext=true`、准确 `authorityIntent`、当前 `billing` 和 `replaceKnownUnstarted`。配置原账本时，下一消费者需要与准备所得 `nextRun` 精确对应的现有授权；调用方不能拿原消息的 payload 授权替换它。角色没有可用的源授权时只停止该新调用。

本片段不接管外部原写者、不恢复已结束的临时原生会话、不处理任意中间消息重发，也不把资源供应方未知状态转成退款。无 PR 接入、原负责人待办、其他写权交接、五类人控制和 X1/X2 仍在原52场景继续。
