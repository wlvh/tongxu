# 原退回记录的正常处理入口

对应唯一当前余项 `completion-coverage.json.currentRemainder.items[F04]`，保留原 T31/T52 及关联要求。已固定的 f847 本机试用版继续可用，本连接在原开发分支推进，不把其未完成状态变成已交付流程的新前置。

用户选择已登记的原任务/退回计划，开始原 A 的事实核实、必要修复、固定测试和新候选独立审核；已有反证成立且配有准确计划时，请原接收者作新的独立判断。没有问题不制造修复，缺接续计划不声称完整闭环。

可信配置固定原 store/item/operation、计划及摘要，页面只提供开始、核查并接续、核查未发送并关闭。HTTP 和报告不能提供路径、程序、命令、findings 或新权限。执行继续调用原 `runQueueRepair`、`closeUnstartedQueueRepair` 和 `runMemberRefutation`，保留原控制器锁、写者/工作区状态、候选、来源、权限和资源门。正常审核反馈回 A，不自动转移负责人；新原生会话如实记录。

显示状态由原 `operations.repair`、固定输入和结果 blobs、原生与工作区原件、反证关联及原接收记录重建。内存中的按钮忙碌/错误是本次入口的观察，不是新的操作账本；冲突以原后端为准。只读查看不会启动模型、刷新授权或修改原执行；明确接续也不能绕过活跃/未知。完成的旧结果仍可读，新候选必须重新核适用性。

完整报告沿原队列保存的 request/result/evidence 摘要定位原执行，再核封存终态、固定输入和会话/轮次捕获，展示事实核实与实施会话的每轮完整最终原文、独立影响报告和独立再审。不能仅展示终态 `data.review` 并把它称作全部报告。缺原件或摘要不一致时明确保留不完整状态，已有结果仍可查看，不补发模型任务、不重写旧 result。历史阅读核原始材料，不用今天工作区的变化否定过去已经保存的报告；这些旧报告也不授予当前写权。

原修复控制器由每次短期受管工作进程调用，进程结束与页面服务寿命分开。父入口保留实际启动、PID、输入、退出与原字节，显示和后续选择仍读原队列，不能用退出0替代终态。这样部分修改后可在同一页面核原进程确实结束，再按原规则接续；不删除写者标记、不放松PID检查。入口关闭后停止接新的动作，也不再自动启动下一接收阶段；已经发出的原处理仍保留。

验收从实际页面流程核到原结果：正常退回、实际修复或成立反证、固定测试及独立新判断、完整原文、重复/重开不重发；原候选、写权、占用、停止、部分输出和未知恢复分别有反例。既有真实执行器证据按未变接口复用，页面和失败样例明确标记，不用测试数或模型PASS替代用户成果。
