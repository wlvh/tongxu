# 用户本机 Claude 核实交接

本环境没有 Claude Code，用户已明确本地继续无新增认证/费用的工作，Claude CLI 环节由用户在自己电脑运行。这里提供可交接的材料和实际检查次序，不代表已运行 Claude、已有费用许可或完成双引擎验收。不要安装新订阅、迁移身份或接管既有生产会话。

## 固定材料

交付时提供独立私有交接目录，其中 `manifest.json` 固定每包 H/B/真实 target、原始报告/索引 hash 与技术判断；源码按固定提交导出到 `candidates/`，适用 main/B、完整固定上游提示、现有 Codex 审核报告与必要原件另存。先核 manifest 和原件 hash；任一版本变化都需重核适用性，不能复制旧 PASS。原始记录私下交接，不粘到公开 Issue。

在新的本地目录解包，先收集已有 CLI 的实际能力：

```bash
claude --version > claude-version.txt
claude --help > claude-help.txt
```

若该命令不存在，保留未执行状态。本轮不要求安装或新认证。按实际 help 使用新鲜独立会话，隔离作者聊天、自动记忆、隐藏状态与原生产项目配置。只授权读取交接目录的文件/搜索工具；不给 shell 执行、写文件、网络、发布、merge 或业务工具。若本机版本不能落实这些限制，不仅靠提示冒充只读执行器，记录能力缺口。当前仓库未验证 Claude 版本/flags，因此不把一组猜测 flags 写成已验证的自动启动命令。

## 发给独立 Claude 的核实任务

装配 `main` 和适用候选的 `prompts/runtime_contract.md`、单角色 `prompts/verifier_impact.md`、完整固定上游流程/必要审查提示，再加以下本轮输入；不把所有角色拼到同一会话。

> 对 manifest 中每个固定候选分别做影响核实。读取原 Issue 条款、真实 B/target、额外未合前置、本批 Codex findings、对应修补和原始证据。重点核消费者、相邻入口、旧状态兼容、保存/复用、证据来源、副作用及多 PR 组合。区分实测、读码推断、他人报告、未检查。不要把测试数、JSON 有效、作者声明或相同账号当独立通过。现有 W1/W2/W3/W4 能力各有明确局限：W3 仅本地 shadow，W4 仅隔离元数据自检。不给完整 G1/G2 或生产动作放行。
>
> 给出判断 ID、任务类型、实际模型/CLI/提示/工具版本与固定 H/B/target；逐项说明支持或反例、影响、最小修复、必要验证、未检查。没有有效 S/r 授权材料时标记缺失，不能造签署。只读，不修作者现场、不合并、不新增目标。只接受你本轮顶层最终结果为核实报告，中间文字或子代理 PASS 不算结论。

结果保存自然语言全文及原始 CLI 输出，记录会话/运行引用、起止时间、退出/中断、实际工具权限与输入 manifest hash。私人会话标识只私下返回。负责人收到后按固定候选做 Codex 事实综合；新反例按原授权修复、重新独立审核，不自动合并。影响核实不等于 PR 接收或用户成果接受，这些仍各有边界。

## 原生 Claude 接入与下一阶段

代码影响核实可先做；完整 W4 还需要本机实际版本协议、精确 session/turn/workspace、两轮输入、顶层最终结果、错误/等待/批准事件，以及可落实的角色工具边界。先回传 version/help 和现有能力的记录，再依据该版本细化适配；不要在未知费用/认证条件下试发模型任务。不能把人工复制一份核实结果称 W5 的自动链搬运已完成。

W5 可复用这些真实记录细化 Bridge 和自足 #7；自动审核→核实→综合→授权修复依赖真实角色执行器和精确最终结果接入。相关依赖等待时，已授权的独立开发/测试继续；不因此绕过独立性或无限堆叠不稳定分支。
