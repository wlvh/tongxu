# 读取真实任务状态的受限秘书

接续 #6 的受限秘书前置。本子范围从 PR23 `390a54b6898dda44af083183c24184e948beb493` 建立 `feat/w4-readonly-secretary`，真实 target 为 `feat/w3-result-publication`。固定原队列已有真实接收、补充和发布结果；本项让一个独立 Codex 秘书实际查询这些记录，回答进展、待核事实和下一步。它不作技术审核或接收判断，不申请生产写权，不宣称完整 G2/W6/W7 已完成。

SQ01 可信操作者指定原 queue、单个 item、准确候选/范围、现有 Codex、完整公共及秘书提示、已有订阅边界和一个有界问题。角色固定为 secretary，不能把 reviewer/verifier_fact 改名充当秘书。原用户问题和队列记录都不是新增工具或权限的来源。输出保留候选、原会话/turn、问题、实际查询与最终全文。

SQ02 复用已经验证的官方原生执行器和受控工具转发；新角色只注册读取选定任务状态、读取该任务某次 operation 两项查询。没有任意路径、SQL、shell、业务代码读取、测试、写入、发消息、发布、批准或 merge 工具。原修复角色保留原工具和行为。每个工具请求核准确根会话/当前 turn/call/工具名与参数，最多八次；模型不能选择其他 queue、item、账号或执行器。

SQ03 后台以 SQLite 只读连接读取原账本，在同一次读事务中投影本任务的候选、材料完整性、停止、占用、实际 operation 阶段、接收枚举及当前发布记录。只传需要解释状态的字段，不交付源代码、模型报告、凭据、私人路径或任意来源文本。记录观察时间、账本事件水位和投影 hash；这是本地记录的观察，不冒充新 GitHub 检查或外部流程被控制。SQLite 可能正常维护读连接的共享内存，保证逻辑行不写入，不保证数据库旁文件的物理布局不变。

SQ04 在发起新模型 turn 前核本人已有订阅、普通用量及本任务停止新增投入状态。内建 shell、网络搜索、插件、MCP、自动记忆和子代理保持关闭；官方受控工具 host 只转发上述注册查询。秘书离线不影响原 CLI 直接控制。已经发起的任务保留原捕获，停止或未知不伪称取消，也不启动替身。

SQ05 单次 CLI 入口完成查询问答。先保存固定计划、提示、问题和运行意图，再启动一个新的独立上下文、一个 turn；最终答案必须来自匹配的顶层最终消息，且实际执行过注册查询。机器观察与模型解释分别保存；解释中的建议不执行、不成为批准。模型引用只能指向本轮实际查询记录。重复入口回读原结果，不重新提问；部分/失败/错误版本/未知会话保留原件与明确状态。进程互斥绑定本运行目录，已发未知不因锁释放重发。

SQ06 验收一次真实 Codex 秘书询问原任务的接收、发布和剩余边界，实际查询后台并返回完整回答，用户不搬报告。独立检查工具清单/调用、角色/原会话、原队列行与原捕获不变、重复入口零新模型。安全夹具覆盖越界工具/参数/operation、错误会话、部分或等待结果、重复和未知不重发、停止及查询数据变化。保留原修复/解析回归和必要独立代码审核；不为演示制造业务缺陷，不更改认证、额外费用或生产权限。

入口：`secretary-cli run --plan ABS_PLAN --output ABS_NEW_PRIVATE_RUN`，再次使用同一计划和同一输出目录只读取已完成原运行。这个入口没有协调派发或控制能力；后续 W6 的双任务协作须另按实际接口细化，不能由本次问答推出。

## 当前正常入口连接（2026-10-23）

上文是原只读子范围。后续已增加固定任务联系、成果及本人控制/复盘的同源查询；[本次原 #9 接续](https://github.com/wlvh/tongxu/issues/9#issuecomment-6355882627)进一步连接工作台提问、获准催办/队列偏好和有界定期补查。仍复用原秘书、原 TaskInbox、EventRecords、来源核实与权限记录。

页面只接收有限问题、已选任务和请求 ID。执行器、完整提示、工具目录、输出根与订阅边界由可信配置固定。先保存原请求，再运行原秘书；登记、实际输入、完整返回、等待/未知分别显示。刷新不发模型，重复 ID 不换输入，已发未知先核原捕获；秘书离线时原直接控制仍可用。

催办工具只选择固定提示内容，返回原 hint 回执，不将它称为已派发或已完成。队列偏好只选择固定 payload，按原秘书角色的 coordinate 授权重新核来源，再沿原 reserveAction/applyPreference 保存；逐次确认与有限委托按各自原规则消费，不复制或扩大批准。直接按钮使用同一后端和回执。所有模型输出均为数据，不能产生新参数、权限或命令。

定期检查连接原 sourceTick 和固定 profile，沿原间隔、范围及跨进程锁运行。它只补查来源/原材料，空变化和重复检查不调用模型或合并。前台入口关闭后不再发新检查，已开始的原检查按原执行结束/未知记录保留；不安装常驻服务。验收包含漏一次通知后的实际到期补回、重复/重开、无权偏好和原素材变化，以及同一页面的原秘书完整回答。真实工具面变化另做一次有界原生核实，测试样例和真实结果分开。

计划固定 `schemaVersion=1`、`kind=tongxu-readonly-secretary`，其余字段见 `SecretaryPlan`：store/item/candidate 来自原队列；codexExecutable/codexSha256 来自现有官方程序；prompts 恰为公共运行边界和秘书文件的 path/sha256；question 是一次进展问题；scopeSource/arrangementSource 保留已有采用来源。disabledMcpServers 与 allowedInstructionSources 取实际原生配置与允许的固定文件，不能用默认空数组忽略现有权限。

本角色只使用 Codex，费用依据也须对应 Codex。billing 保留 mode/evidence/evidenceSha256/observedAt，并固定 `ordinaryUsageRequired=true`。现有账号可以已有 credits；本字段不声称账号余额为零或额外额度已经关闭。新原生连接核 ChatGPT 认证，每次发送前核 `ordinaryUsageAllowed=true`，拒绝 API 覆盖，固定普通 service tier；不可用即停，不启用额度或切换新计费路径。证据超过24小时要求刷新相关只读预检，不重查全部认证路线。

共享原生封装还修补了一个已复现的时序问题：turn 接受回复和首个工具请求可能同批到达。工具处理先等本程序已提交 turn 的准确回复，再核 thread/turn；不采用工具自报ID。原修复角色工具和提示保持原边界，回归保留修前失败和修后结果。

恢复从固定计划重建完整 initialize/认证/配置/用量/thread/turn 请求、顺序、ID与参数，并核原始回复中的认证、配置、只读权限和准确接受的 session/turn。原 expected-requests 与 hash 只保字节，不自行证明权限。工具回复必须对应原服务端请求和已保存查询；相同请求的重传可严格复用同一响应，不能夹入无请求的响应或重做查询。历史等待记录保留；只有原进程后来确有完整匹配终态时，才允许只读恢复为完成，不发新 turn。
