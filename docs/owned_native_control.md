本子范围直接补原有缺口：
1. 只针对同序显式创建、保存原始启动记录及准确角色/工作项/候选/许可的原生上下文提供控制。保持既有只读关联入口；不搜“最近会话”，不自动接管外部 App/IDE 会话，也不扩大工具边界。
2. 原进程结束且其状态、请求和工具副作用可核后，按准确 thread/session ID 续接受管持久会话。核版本、工作区、原权限/工具来源和当前授权，确需新上下文时明确标新上下文。原 ephemeral 或来源不充分时拒绝 resume，不启动替身。
3. 对本执行器拥有且准确处于进行中的 turn，提供限定的补充输入（steer）与中断（interrupt）。绑定 expectedTurnId/turnId 和原请求；回执、事件终态、最终答案分别记录。中断请求被接受不等于已终止；steer 失败不降级为 turn/start。
4. 故障恢复先读取原请求、输入和原始事件。已发或未知动作不重复投递；新进程不能凭旧 idle 元数据夺取运行权。保存准确新旧会话关系，部分答案不当成完成。未实测的 pause 等能力保持不可用。
5. 复用原 QueueStore/session/message/权限资源记录和互斥，分别核角色工具、组织/停止条件与原生能力，不建设通用会话迁移平台或第二套操作账本。原执行器无法落实的限制必须具体显示。
6. 以本机实际版本、明确小范围非业务任务验证有意义的续接/补充/中断结果；错误会话/turn/版本、等待、部分输出、重复入口和中断恢复用安全夹具。保留全部原帧和失败，费用沿已有订阅内限额，不启用Extra usage、不迁移认证或切API计费。

组件已按下方记录实现并独立复核；仍需原队列与界面的完整连接。不能把 schema、代码存在或新建会话成功直接算作用户流程通过。继续让工作台显示实际能力与运行结果，再完成原完整用户流程和52条验收。无main直推、合并、自批、部署或SEC操作。

## 当前实现和证据边界

`BoundedCodexSession` 已增加显式拥有的运行控制。持久续接目前仅支持无工具的只读角色；继续使用原操作的控制互斥、固定候选/系统输入和当前授权回调。运行中的补充/中断绑定准确 thread/session/turn；重复已确认动作只回读，结果未知不重发。中断回执不表示终止，需看到原轮次终态。原始解析器的默认交接规则未放宽；显式受控的新轮次可以接在已知中断之后，但旧中断仍使整段历史不能作为完整成功交接。

本机已取得一次限定组件实跑：一个固定源码检查会话，四个不同的实际轮次（完成、完成、中断、完成），一次补充输入、一次中断、两次退出后按原 ID 续接。总共一个 `thread/start`、两个 `thread/resume`，无工具或业务写入。真实 resume 不重发 `thread/started`；读取器按摘要关联原始捕获，在内存中按顺序读取原字节，不制造创建事件或改写日志。空会话缺 rollout 的先前失败保留，不能被正向例子覆盖。

组件实跑与原件清单位于本机 `native-control-preparation/actual-native-01`、`actual-native-02`、`actual-native-manifest.json`。源码及编译模块摘要另存；这是未提交候选的执行记录，后续需核与固定提交的适用性。63 项受影响的本地协议/解析/秘书/修复/归档测试通过，包含实际进程和 Git 测试；其模型角色明确为夹具，不能冒充上面的真实调用。

组件独立复核已经完成，后续原 QueueStore 消费者及工作台连接见下节。低层回调或成功日志不是权限来源；普通 session 关联也不授予控制。旧只读/短期执行仍沿用原路径；不会因本次新增接口自动获得持久续接能力。本候选在 Draft PR #61 中持续完善，不将此组件检查点计作 T26/T32 或全部 52 项完成。

## 同一 PR 内继续连接原队列与工作台

可选 `nativeControls` 属于原 `MessagePlan` / `TaskOwnerRequest` 的固定输入。每个选项指定原消息、补充全文或中断、唯一 ID 与显示名称，最多八项；只支持已核实的 Codex 入口。它改变原计划摘要，因此原 `coordinate` 授权及资源仍必须对应这个准确计划。默认短期只读消息不自动获得控制。

新的消息模式复用 `BoundedCodexSession`，沿用原角色全文与无工具限制，输出准确消息收据；不把 Issue 负责人伪装为审核者。工作台只持有当前入口实际启动的控制句柄，不能用关联的 session ID 重建权限。网页只能选择固定补充，提交所见 thread/session/turn；不接收新 shell、工具、角色或任意运行输入。发送前刷新原候选、范围、权限、资源和用量，并在最后同步发送处复核。所有控制意图与回执进入原 `events/blobs`，先保存意图再产生副作用，没有第二套队列。重复或结果未知的控制不重发；中断回执与实际终态分别显示。

补充的摘要必须出现在最终原文的消费列表中，否则回复不能作为完整处理结果。准确中断作为 `Interrupted` 保留，既不成为成功报告，也不转发后续依赖。已停止或撤销时仍可中断自己拥有的原轮次；该动作不授权新投入。配置原资源时，已核实的单条中断执行按失败事实交给原供应方结算，不推断退款。

原进程结束、原捕获核实且资源结果成立后，可以显式“保留中断结果并结束此请求”。随后 A 可处理另一个已固定且经原授权的新请求，保留上次输入和中断事实；默认新上下文与下节新增的显式原生续接分别记录。原件损坏、活跃或未知执行、未结资源均阻止这个结束动作。按钮不会因 persistent 记录存在而自动开放。

定向测试使用实际本地进程、SQLite 与 HTTP，但模型、本人来源和资源供应方明确为夹具。它们验证准确补充、重复回读、停止后中断、第二控制器拒绝、候选变化、撤销、原中断结算和 A 的明确后续请求。真实消费者记录与入口装配在下节另列；这些测试不代替完整本人控制旅程。

`70657d8` 的独立复核保留了两个缺陷。TNC-F01 证明材料可在最后一次资源查询等待中改变，旧队列快照仍允许补充发送；修补把来源刷新放到资源/本人查询之后，发送前同步核对已观察的指定文件及 Git 身份，已关联任务同时核选定暂存内容和执行位，再进入原权限/资源检查。这里不声称获得跨进程原子文件系统或通用工作区锁。另一项 TCN-UI-F1 证明遗漏补充消费摘要的完整原文虽保存，却因空的已验证正文无法从页面读取；修补保留未确认原文的阅读能力并清楚标记消费未确认，不把它变成任务成功或可按中断关闭。原 REWORK、实际反例、首次界面超时和失败测试日志均保留；两项已分别在 `a8992a5` 的独立定向复核中关闭。

## 原任务中的显式原生续接

`nativeResume` 是一个新的固定请求字段，准确指定原 `run`、`participant`、`messageId` 与原捕获文件清单摘要。它不包含任意目录或外部会话 ID。TaskInbox 要求它来自同一任务已选定的原负责人输入；原负责人、候选、材料包、范围、角色全文、执行入口及工具边界都保持一致。普通新上下文联系，以及“把尚未发送的最后一条消息交给新上下文”的既有 `continueMessage`，不被改名为原生续接。

原请求必须有完整捕获和准确结束事实：完整回复已确认消费，或原中断已核实且由原任务明确关闭；配置了资源时还必须核原供应方结算。新输入使用自己的准确计划摘要、本人授权、用量观察与原供应方请求。原报告或保存的会话 ID 不授予这次输入权限。先核原捕获，再占用新的资源；消息控制器、原控制器和原生操作互斥沿用现有机制，活跃或未知执行不会因新目录或新请求 ID 被绕过。

执行层核对所有原物理捕获的摘要和大小、原进程结束、新旧角色及原生绑定，再调用已有 `thread/resume`。实际 `thread/read` 必须返回相同的 thread/session、准确的完整历史、空闲状态和原受限工具配置。此时才记录 `nativeSessionResumed=true`。失败不会退化成新建上下文。新捕获写入原操作下独立的续接子目录，原 `native/` 文件保持原字节；重放按原链读取，新消息只消费本次新增轮次。源代码或真实会话历史变化时保持拒绝，不将新候选冒充旧会话的已核实候选。

工作台的固定联系可以显示“继续原会话”，同时展示原请求引用和“请求续接”或“执行器已实际续接”。新轮次仍支持准确补充、中断、完整原文查回与原资源结算。已发或未知输入不重发；仅有元数据、确认没有输入且进程结束的启动失败，才沿原请求最多重试三次。原中断记录仍是中断，不随下次成功变为完整报告。

新增本地回归使用明确的模型、本人来源和资源供应方夹具，覆盖同一会话的新轮次、保留原文件、重复零输入、中断后显式续接、错误捕获及候选、真实历史不匹配、第二控制器、旧 turn、撤销后准确中断与结算。组合检查发现并修补了内部资源准备路径遗漏原结算查询的问题；原失败和诊断副本保存在 `owned-resume-preparation`，没有放宽结算要求。这一增量仍需固定候选独立复核、实际浏览器及真实消费者证据；此前组件真实 resume 不移作本次完整用户流程通过。
