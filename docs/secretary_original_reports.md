# 秘书读取原接收报告与正式收尾记录

用户从正常入口选择原任务并提问。启用了本项读取能力的任务，秘书可以读取操作状态列出的接收报告全文、具体问题、原候选和范围，并通过已有只读来源机制取得该任务及明确选择的相关 PR 记录。用户不需要搬报告或装配本次问题文件。

任务页与秘书共用 `QueueStore.observeReceptionReport`。操作必须属于所选任务；历史报告、首次证据不足、后续补充、判断全文及摘要保留。查询原报告不会把它改成当前材料的接受，也不会重新发送模型任务。

正式来源使用既有 `readEventSource` 与只读 `PublicationHttp`。任务绑定来自原队列，来源配置摘要和同仓库相关 PR 清单由可信配置固定；模型不能传入 URL、其他仓库、命令、权限或临时扩展的 PR 编号。每次查询保存实际响应和观察时间，重读已完成问答使用原捕获，不再次刷新远端或调用模型。某个相关PR暂不可读时，仅记录该来源缺项，保留已读的原任务记录；相关PR的仓库或对象身份不符则拒绝；原任务来源身份未核实时，不向秘书交付该正文，仅保留缺项。原HTTP正文完整保存在原捕获内，给模型的来源观察限制在128KiB，最多呈现最新32条评论；省略的正文有摘要与明确缺项，不截短后冒称全文。历史接收报告全文不受这项来源投影裁剪。来源观察分别标明原来源读取是否完整、相关来源是否齐全、给模型的投影是否完整；总的sourceReadComplete表示这些条件都满足。

回答必须分开解释：历史接收得出的结论；旧材料包当前是否仍适用及其具体影响；正式来源记录中的关闭、合并或其他收尾事实。旧队列等待不自动表示今天的开发未完成；关闭记录也不证明全部验收或本人采用。来源记录缺失、读取不完整或内容矛盾时保留缺项，不硬编码“已完成”或“已合入”。

新增工具只在计划显式选择 `receptionReports` / `taskSources` 时注册。旧问题保留原模板、工具表、协议及原始输入，不借新增能力重写历史。报告和来源正文仅作证据，不授予后续行动。角色契约已在原系统输入中装配，无须向秘书开放文件系统以再次寻找它。

本项由 #9 的现有 F09 跟踪，独立于 #63 的网页登记恢复修补；它不成为 CLI 修正的附加合入条件，也不要求先完成 #10。实际试用与明确测试程序分别留证，完成本批声明流程后交由用户判断成果，不继续扩展通用接入或调度。
