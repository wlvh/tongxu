## 本地启动

使用已有 Node 24 和同序构建。配置在仓库外的私有目录中，选择准确的 queue/item；不要放供应商凭据。配置内容示例中的路径/ID必须替换为实际已有对象：

```json
{
  "schemaVersion": 1,
  "kind": "tongxu-local-workbench",
  "title": "接收与协作现场",
  "goal": "本批真实用户目标及当前查看范围",
  "sources": [{ "id": "selected", "title": "所选任务", "store": "/absolute/private/queue", "item": "REPLACE_WITH_EXACT_ITEM_ID" }]
}
```

```sh
npm run build
node dist/src/workbench-cli.js --plan /absolute/private/workbench-plan.json
```

终端返回本次进程的本机URL。用完整URL打开；临时查看标识只允许读取这份配置的任务，不能充当本人采用或执行授权。地址只监听127.0.0.1，适用于本机浏览器，不是手机远程访问或部署。Ctrl+C关闭查看进程，原队列与原运行不受影响。刷新不会调用模型。

任务页可查看准确H/B/target、来源观察时间、当前查看时间、历史与当前报告，以及已登记的停止状态。完整报告按原文文本呈现。协作页来自原events；本地检查与真实发送分别显示，重入产生的检查也仍作为历史保留。各队列分别读事务，不宣称跨库同时快照或远端最新状态。

7项后端检查验证原记录不变、身份/跨站/方法/越界路由、完整原报告与HTML数据隔离、阶段语义和来源失效；页面本身还需真实浏览器的桌面/窄屏/主题/键盘检查，不能用HTTP测试代替视觉验收。公开示例不包含真实查看标识或私人原报告。
