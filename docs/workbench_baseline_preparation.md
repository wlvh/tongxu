# 接受基线到原整体复盘

继续原T51/T52与正常使用流程。目标采用和接受基线分别记录；目标已采用不意味着本人已接受当前能力，更不授予新的执行权限。

“目标与边界”可以固定目标、规则、能力及证据说明三类原文。页面提交内容，程序保存原字节并生成既有 `accept_baseline` 请求，摘要绑定全部三类内容。查看完整原文使用原队列保存的内容，不接受任意本机路径。采用前核准确基线来源与其原目标采用来源；共享身份、改动或缺失来源不能成为接受证明。原材料、旧采用与失败均保留。

“判断与复盘”从启动时已固定的复盘材料选择已记录接受的基线，自动装配三类基线原文。累计变化、当前行为、当前文档、执行器和订阅边界仍来自原选定计划；页面不提交新命令、可执行文件、资源数量或费用开关。新请求、本人接受基线、准确执行授权与模型运行分开显示。

复盘准备链接仍保存在原events/blobs。实际执行、未知状态、重试上限、完整捕获与资源回读继续由原OverallReview/ReviewRecords/资源消费者处理。资源需求使用选定计划中原资源请求的固定引用和数量，新动作另核原权限；不复制已消费的许可或凭空增加额度。相同原操作有已发未知复盘时，不通过新ID替代。所选原任务的准备历史在写入前限64条，原材料可查。

秘书从同一固定工作台选择读取派生复盘与完整报告，只允许所选材料计划的准确派生记录，不开放新工具或发送权限。新的查看阶段不调用模型。正常安装暂保持520，四个真实任务缺独立本人来源的事实不变；测试来源不进入原队列。

当前开发检查已通过基线准备、来源变更拒绝、原治理复盘、同请求重复、停止及未知恢复的相关场景。仍需固定候选的独立复核和实际页面检查，不能把这份说明或夹具运行算为真实本人采用、业务无偏移或全部52项验收。
