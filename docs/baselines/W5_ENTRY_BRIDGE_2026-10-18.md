# W5 接续前置：以实际角色执行证据细化

这是 W4 子版交付后的具体接续记录，不是新产品版本或 W5 已开工/通过。既定范围仍为 v2.3、#2 连续开发安排和 #7。W1/W2/W3 已有可用分支软件，W3 为本地 shadow；W4 的真实 CLI 只验证新隔离现场的元数据协议。各阶段 Draft 未合并，权限和必要审阅不因此满足。

| 实际输入 | 可复用的事实 | 下一项必须取得的证据 |
|---|---|---|
| W1 #13、W2 #14 | 固定 H/B/target、原始材料、隔离执行及逐前缀报告 | 原报告的真实执行者/权限不由 hash 自动证明，仍交独立核实 |
| W3 #15 | 持久原 operation、精确前置、停止、冲突、占用与重启 | 只做本地 shadow；未获得独立接收、生产授权、发布或条件合入能力 |
| W4 #16 | Codex0.159.2 隔离初始化、准确 thread 元数据、拒绝错误 steer、再次 idle、原字节留存 | 尚无模型 turn、两轮交互、顶层最终结果或秘书无 shell 的有效工具限制 |
| 用户本机 Claude | 用户明确由其电脑承担；本环境不新认证/费用 | 本机实际 version/help、读取工具限制、独立会话与影响核实最终原输出 |

## 下一项已获准接续

1. 用户在其已有安装上获取 `claude --version` / `claude --help`，按实际能力使用新的独立只读会话核实固定交接包。输入 manifest/原件与结果边界见 [本机核实交接](../local_claude_verification.md)。认证、费用及工具限制没有可核依据时不发模型任务。
2. 负责人收到实际版本/能力和结果后，核固定候选适用性；普通技术缺口在现有范围内修补，不再询问“是否开始下一包”。先依据真实协议补 W4 适配与所需故障恢复测试，把实际两轮/最终结果身份与夹具分开。
3. 将 W4 可消费的原生 run/session/turn、最终结果/失败/配额状态、实际角色工具限制写入 #7 的自足实施条款与源，发布读回后实现 W5 审核→核实→综合→授权修复接续。缺失的字段不以本地自造 JSON 补成能力；不把人工传报告称自动链通过。

W5 的正式自动链尚缺真实角色接口/最终结果前置，当前不能用元数据自检替代该前置。独立只读开发和测试没有被一并撤销；遇到这些具体输入缺口时保存固定分支、源码、证据和下一步，不启动常驻空循环或堆叠未验证依赖。主干合并、生产接收、身份/保护、费用等权限各自核验，#10 的治理不成为只读工作的前置。

此记录不修改 #7 原验收 T13/T19/T22–T27/T33/T34/T44/T50/T51，也不自批真实修复超过三次时的既有简化反思。原生能力和固定候选变化时重核，只暂停受影响动作。
