分支 `feat/w3-governed-publication` 从固定 `1d56ed2f888b21362708e403716bbc6776be683e` 开始，target `feat/w3-refutation-authority`。前置采用 #53 `29b2933` 的完整修补，反证授权自身适用性复核中；前置若有普通修补将显式采用准确新H，保留全部历史。

现有 publisher 能生成允许公开的固定摘要、写明确选定的 commit status + 详情并回读，但配置 Owner 来源后，旧发布入口按设计被拦截。本次补准确 publish 意图、原资源及实际发送门，继续原QueueStore/events/blobs、原发布操作和provider，不另造消息／额度系统。

1. 固定原接收、准确候选/packet、公开投影、实际执笔者、仓库、明确选用的通道与固定执行文件。许可绑定这些准确输入摘要，仅 background 发布角色可执行；旧receive/test/implement许可不能借用，模型报告不能带来新权限。
2. 每个实际POST在原队列事务内重新核来源、停止、授权和原held资源，覆盖子进程启动与首输入。原始请求/输出/退出与远端readback分别保存；详情成功不等于status成功，HTTP201或退出0不替代精确回读。
3. 已发未知只查原对象，不重发；明确拒绝沿原受限重试规则继续，候选变化/撤销只阻新写，历史事实仍可回读。原资源结果只按核清原发布结算，部分发布/未知保持原请求，不凭文件或报告释放。
4. 默认未配置治理的入口及明确commit-status通道保持兼容，不新增check-run身份、双写、认证或费用。固定公开摘要继续排除私人报告和任意模型链接。
5. 本子范围先用明确本地Owner/provider/原生形状/远端CLI夹具，实际进程与存储检查准确授权、旧入口拒绝、发送前停止、部分写入、失响应、重复和恢复。0新官方模型或真实业务发布。独立核实后交单独Draft；随后继续RETURN准确回执到原负责人、实际远端候选桥接及原R1–R6，不把发布适配当全部R2完成。

## 当前实现检查点

已实现准确发布计划解析与权限输入摘要；摘要固定公开材料、原operation、仓库、执笔者和执行文件，排除许可／资源ID，避免循环绑定。该新解析器尚未接入旧publisher，不能据此使用治理计划发出请求。

PublicationHttp新增同步dispatch回调，可让上层原队列事务覆盖intent、spawn、started和首条输入。它分别保留提交前意图、管道提交记录、真实退出与dispatch异常；事务提交失败发生在输入之后时，仍保留“可能已提交”，不会改记未发送。旧无回调路径保持原入口行为。

构建及18项测试通过：4项新契约／实际进程事务与异常证据检查，14项原发布回读、停止、竞争、未知响应、明确拒绝、SIGKILL恢复和隐私边界回归。全部为明确本地夹具，0官方CLI／模型／GitHub请求。治理许可、原资源消费者及提交后事务回滚的原运行恢复仍需接入；当前不是完整发布能力交付。
