# 原任务联系与直接控制

接续 Issue #9／#6／#8 的可执行秘书与直接操作部分，固定前置为 `feat/w6-task-candidate-link` 的 `360fa7760a11302c155db1890969f617acf3eb1d`。前置尚在独立修复复验；如有修补，核对后接续准确版本。独立分支 `feat/w7-task-controls`，真实 target `feat/w6-task-candidate-link`。所有原 Issues 和 52 场景保持在目标中。

TCU01 本机启动配置明确选择原队列和任务，并固定少量联系请求的原文、文件摘要、角色、工具、费用证据和既有授权引用。页面和秘书只能选择这些已装配请求，不能提供任意路径、可执行文件、权限或 shell。读取页面、刷新和查询均不发模型。

TCU02 直接操作和秘书共用同一个后端，程序登记准确原待办，准备完整上下文，调用原消息执行器，再读取原回执和报告。原候选、源文件、负责人责任、授权、资源和工具检查继续在实际发送前执行。按钮和秘书文字不是本人批准来源；配置文件属于操作者已有的可信启动边界，不是通用本人身份认证。

TCU03 请求登记、处理正在进行、已送达、返回、材料过期、未知和等待分别呈现。重复点击、并发客户端、进程中断和丢回执仍核同一个原待办／run，不新建相同模型任务。尚未发送且无未知责任的请求可以撤回；已发送或未知的请求不能用撤回冒充停止执行或返还资源。

TCU04 工作台提供准确任务上的联系按钮、有限待办撤回和完整报告回读。默认既有只读入口不增加写能力；控制模式显式启用，保留 loopback、临时访问标识、Host/Origin、严格路由和有限请求体。浏览器请求不能改变角色、选中范围或启动配置。秘书只有联系工具，没有本人采用、技术判断、实现、测试、发布和合并工具。

TCU05 秘书获得实际工具清单和动作摘要，调用后引用原待办和 run。新的协调模式与既有只读秘书分开，旧捕获继续按原工具边界回读；原生协议和工具结果必须来自实际执行层，不能用 prompt 自律代替权限。秘书离线时，直接入口仍能使用原记录完成允许的动作。

TCU06 通过实际子进程和明确故障夹具验证正常联系、重复、并发、未知、候选改变、撤回竞争、越界工具／请求、秘书离线、原权限资源拒绝、真实 UI 与完整报告同源。必要独立复核后，再按既有订阅和有界预检取得实际模型工具调用／负责人消费证据。原失败保留，不声称尚未完成的五类控制、X1/X2、完整 W7 或产品全部验收已完成。

## 已实现入口

既有 `tongxu-local-workbench` 仍只读。显式配置 `tongxu-controlled-workbench` 并给出 `controls: {path, sha256}` 后，页面才显示联系与未发送撤回。启动命令仍为 `node dist/src/workbench-cli.js --plan /absolute/workbench.json`。配置中的 sources 仍限定队列和任务；HTTP 请求只选固定动作 ID，不接受文件路径、问题、角色或工具参数。

联系目录是 `schemaVersion:1, kind:"tongxu-task-controls", contacts:[...]`。每项包含 `id`、`title`、工作台中的 `source` 名称、准确 `packet`、`sourceSha256`，以及既有 `tongxu-task-owner-request` 原文件的 `request:{path,sha256}`。目录最多八项；相同原待办不能换动作名注册两次。启动时读取并固定完整请求；后续文件替换不会改变已启动实例的请求，新实例会拒绝不符摘要。变更材料需要新的明确配置，不会由按钮自动借用新候选。

`TaskControls` 共用原 TaskInbox 和 MessageRecords，没有第二套任务或资源账本。页面开始操作先登记原请求，再在同一个本机进程内完成有限执行；后续状态和完整报告从原库读取。结束本机服务会等待已经开始的有限动作返回，不再接新动作；强制终止后依原捕获判断，不靠 UI 的内存状态推断成功或重新发送。

秘书的新计划种类是 `tongxu-task-secretary`，另给 `taskControls:{path,sha256,source}`，其余精确执行器、完整角色提示、订阅证据和候选字段沿用原秘书计划。一次仅联系该秘书已选定任务中的配置负责人。真实执行与夹具必须同类；旧只读计划携带此配置会被拒绝。

新模式只有五个固定工具：原任务查询、原操作查询、列出联系选项、发起准确联系、读取该联系的完整原报告。工具参数不能扩大权限；调用在登记前再次检查仍属于当前有效原生轮次。原待办一旦合法登记，执行职责属于原任务程序，可以在秘书会话结束后独立完成；这不是替秘书继续发起其它任务。报告作为数据返回，不能产生新的工具、路径或批准。旧只读秘书的工具列表和捕获校验保持原合同。

实际来源权限、用量证据或资源认领缺失时，原执行器仍拒绝相应调用。此入口不代替独立 Owner 身份、目标采用、成果接受或合并批准；对同一 OS 账号持有任意文件写权的程序，不声称目录摘要构成身份隔离。
