# 同序 v2.3｜人掌控目标，Agent 协作交付

现行设计与实施基线，2026-10-18。文件名保留供已有链接使用。v2.2 在 `archive/tongxu_v22_plan.md`；旧评审不是并行规则。本轮更新的是产品说明、工作流、角色指令、离线 UI 与实施范围，**不代表生产应用已实现**。面向使用者的完整说明见 `PRODUCT_GUIDE.md`。

## 01｜成功标准与实施边界

成功是 Agent 与 Issue 增加时，人的机械决定不同比增长，同时仍能改变方向、限制后果、停止投入并拒绝不合格成果。不是多开 Agent、合并更多 PR 或把每条中间消息展示给用户。

产品仓库 tongxu；SEC_metrics 是只读调查试点。当前仍执行 #2/W0；已有执行者只接增量，不重开任务。本轮修改授权不授予试点代码、Issue、账本、会话、业务调用、合并或部署权。首次支持单用户、单仓库、单台已验证主机；三个顶层责任是验收样例，不是数量限制。

## 02｜角色与原生运行

| 角色 | 默认入口 | 职责及边界 |
|---|---|---|
| 工作秘书 | 独立 Codex App Server 会话；受限同序工具 | 总览、联络、跟进、呈现选择、按既有授权安排。无业务代码写入、任意 shell、测试、技术 PASS、接收或合并权 |
| Issue 交付负责人 | 独立 Codex 或 Claude Code 会话 | 调查、技术方案、在途协调、实现和整体交付；可提议串行或合并责任，不自改产品边界 |
| 子任务实现者 | 独立原生会话或原负责人顺序 Run | 限定实现、自测和产物交接；局部完成不是共同成果完成 |
| 独立审核／核实 | 固定流程的新鲜独立上下文 | Codex 正式审核与事实核实；Claude Code 影响核实；保留原报告，证据而非投票裁决 |
| PR 接收／集成 | 独立 Claude Code CLI 会话 | 必要时提前核交付设计、运行获准组合验证、接受或退回、选择最小安全候选并请求受管合并 |
| 普通后台 | 非模型程序 | 身份／范围核对、寻址、队列、工具执行、正式发布、合并、观测与恢复 |

角色不是固定数量的常驻进程；九份角色 prompt 不意味着九个 Agent 永远在线。秘书不做技术总管，接收者修补的代码需另外独立复核。整体漂移复盘复用独立审核角色的按需模式，不新建常驻管理 Agent。模型和版本可配置，默认入口不是能力优劣结论；认证／订阅／API 成本与可限制的原生工具在 W4 核验。

## 03｜人的投入位置：入口、越界与出口

入口采用的是**本批用户成果及边界**，不是每个内部子 Issue：目标、非目标、必须保留的行为、验收办法、可接受限制、资源和委托。子任务在此范围内由技术负责人拆分，不增加逐项签字。

中间默认自治。普通缺陷、补测试、技术分歧、已授权兼容修改由技术角色处理；超出目标、风险、费用、权限或原来允许的失败含义时，在产生越界后果前提交选择。缺资料和不会修不是 Owner 决定。升级须带已查事实、选项与成本／风险、推荐、仅受阻塞范围及安全默认。

出口看真实成果和关键使用路径。用户决定价值和是否接受剩余限制；重复测试、领域验证可委托独立执行者。不能要求用户亲手跑全部场景，也不能把最后的用户体验当生产前唯一安全检查。技术合入、用户场景通过、正式采纳、入口启用和部署分别记录。

## 04｜五项人类控制与秘书首页

首页优先显示本批目标是否一致、可验收成果、越界待决、委托内代理处置样本、控制是否实际生效。原项目总览、任务／会话／PR、通信与交付仍可展开，秘书与按钮使用同一后端。

五项直接入口：①本批目标与不做什么；②并行／条件串行／统一负责人；③规则、委托和资源限制；④成果接受、停止或继续投入；⑤判断后果与整体复盘。秘书可打开、解释或传递控制请求，不能伪造人的确认。已获授权的低风险协调可以直接办；重要本人控制不因秘书离线而不可用。

每条汇报区分已登记、已投递、已接续、已完成、未确认，并关联原操作。技术待办默认给责任人，不都进入用户审批箱。普通进展集中展示，实质例外及时提示，无变化不空转模型。关闭浏览器不取消任务；主机关机不承诺继续运行。

## 05｜正式来源与决定出处

Issue 保存目标、采用范围、共同验收和决定；原 PR 保存本次代码交付、接收／退回及证据；索引只保存责任和授权入口；原生引擎给出运行事实；原账本给出资源事实；同序保存引用、观测、队列、操作与恢复。

Issue 的验收区明确分开：**本人采用边界 S**、**团队技术约定 rN**、**事实与证据**。S 改变须有相应有效采用；边界内接口、验证、顺序的技术修订可委托，不因每次 rN 更新重新请 Owner。新增 X2 不自动扩大 X1。事实纠错不得冒充规则批准。

决定分类：本人明确决定、代理在委托内处置、待采用建议、事实更新。保留实际执笔者、原始来源、当时委托、对象／版本、理由与后果；机器人转录不是自证授权，共用账号不证明本人意图。关闭材料 Issue 不等于所有产品规则由本人逐条签署，不等于用户目标完成。正式状态与来源仍在原记录，不增一份独立决策账本。

## 06｜新任务与在途工作

新任务先可调查，不立即开始可能冲突的共享写入。秘书找候选相关人；新负责人读实际代码并问原负责人尚未提交工作。路径／依赖命中是线索，不是完整安全证明；未回复不算同意。

第一问是是否值得并行。可并行时仅对共享部分约定：用户目标、写责任、接口与错误／来源／复用语义、消费者、材料、验证、可先做步骤和精确前置。开发方提出、消费者与接收者补盲点，写入已有 Acceptance Checklist；独立小修不设开工审批。

接入区分提出、联系、待当前版反馈、部分可继续、共享可实施。责任／接口／范围变动使受影响旧反馈待核；其他工作继续。公共接口、保存／复用、来源、写责任、新依赖或实质反例改变时通知相关方，不定时互相报到。秘书不裁定技术契约。

## 07｜工作组织：并行、串行与统一负责人

并行适用于可独立验证和安全交付的范围。条件串行必须明确等待的能力／证据、被阻止的阶段和可继续部分，例如 B 的共享实施等 A1 到位，而独立调查继续；不是把整个 Issue A 的关闭当作全部前置。

统一负责人是调整责任，不是同时保留两名写者。对活跃现场先请求停止或收尾，核对原操作、未提交内容、后台副作用与远端状态，才能交接。未知不得抢占；交接待核时仅相关写入等待。同一负责人待办顺序执行，不新增竞争进程。

组织方式和优先级变化要有来源、适用范围、请求与生效状态。已有运行不中途被一句“先后做”强杀；待派发和未来受影响阶段按新安排执行。阶段门由后端检查，不能只有聊天提醒或按钮变灰。串行不能制造环形等待；发现依赖环先停止相关新派发并交技术负责人调整。

## 08｜共同交付、条件合入与节奏

共同 X 是一批用户能力，不等于一个 Issue 或参与 Issue 的全部代码。选已有技术负责人牵头，秘书跟进，接收者独立判断。分别记录开发依赖、合入前置、启用前置和父子归属；资料依赖不自动变代码分支依赖。

作者主动提供本 PR 的作用、固定前置、哪些不必等、消费者反馈、证据和建议顺序；接收者检查当前组合而非照单执行。事件触发为主，低频补查补漏；去重依据候选、安排与实质证据。到点不全合，不默认等整个 Issue 结束。

优先兼容基础 A1→消费者 B1→入口 A2，中间目标都应可用；独立 A3 不被拖住。确实不可安全拆分，先调整拆分；仍不成立才构建最小集成候选，经审核和组合验证后一次目标更新。快速连续合两条 PR 不是原子操作。默认关闭开关不自动证明旧路径无影响。

## 09｜接收队列与新动作控制

严重主干问题优先，其次已验证成果收尾、明确退回和必要上游；其余按已采用优先级、等待与运行成本。实质接收席位初始2可调；等待不占席位，同目标一个推进者。插队短记原因，不中断长验证，不让等待下游压住必要上游。

可单独停止新实施、收回新合并委托、停止本批新增投入；不得混成“暂停一切”。已发送、运行中、未知、已完成分别列出。停止后保留成果与证据；是否恢复、改变目标或结束本批由相应权限作出。恢复新实施不自动恢复合并／费用委托；重启不清空停止标志。凭心跳或超时不得自动杀进程、释放占用或退款／恢复额度。

撤销须在下一次受管动作之前检查。已发请求先回读，不能承诺撤回远端已经发生的副作用。不具备真实中断接口就显示仅阻止新动作及原执行待核，不虚构已经停止。

## 10｜候选与证据

候选保留 repo/PR/H、真实目标/B/merge-base、可选受测树T、本人采用S、技术／接收安排r、政策／提示版本和本轮实际材料。固定 Git 对象与实际读取的 Issue/PR 快照，H1 标签不能配 H2 diff。

证据保存对象、工具／模型版本、输入与覆盖、命令或步骤、环境、预期／实际、退出码（适用时）、原输出、独立性与限制。运行成功、比较完整和业务正确分开。缺页、缺材料、漏样本或工具失败不是“无变化”。

原审核是原候选上的历史事实；当前接收核对 base、环境、范围、安排和新反例，记录复用与补查。patch 相同、文件不交叉、无冲突、CI绿均不自动复制PASS。临近接收集中处理增量，不每个事件全面重审；同H新证据允许重审。追加报告引用不自我触发无限失效。

## 11｜工具、临时组合与 PR 记录

复用项目已有获准测试／对照入口，不复制业务准备器。比较内容、身份、来源、状态和副作用；旧成功未必正确，新拒绝可能纠错。昂贵验证可按风险抽样或复用，公开覆盖限制；工具自身要验证空样本、漏项、丢来源和执行失败等负例。

隔离现场构造固定B/H的组合T；记录Git、工具、输入和方法。不改作者分支、工作区、index，不自动rebase/cherry-pick/push。merge-tree可写对象库，不能声称零副作用；read-tree目录不一定等于HEAD，读取Git身份的测试必须匹配实际候选。

作者／唯一发布者维护PR叙事与Review/Fix Record。机器结果优先check run＋固定详情，不争写正文；仍须完整候选绑定。W1仅产出发布无关包，W3核验实际权限；无法发布则明确保留包或选择status路径，不提权或双写。并发修改不覆盖，写后读回不冒充远端原子锁。

## 12｜授权、身份与资源

只读／影子、逐次确认、有限委托三模式保留。有效来源、角色、repo/target、动作、S、必要门槛、资源、时效和撤销匹配后执行；已有授权不逐PR重批，没有授权不扩大。

本人入口与Agent执行／发布凭据分离；GitHub approval是可选来源，不是唯一入口，须核作者自批限制和动作语义。秘书工具与按钮共用后端但不共享本人身份；模型输入不能伪造确认。后台和原生工具限制共同生效，仅贴prompt不算隔离。秘书无shell、写代码、测试、review/accept/merge或批准工具；不可限制则不开控制模式。

首版防误操作和顺手越权，不承诺抗同权限主动恶意进程。执行／测试不带人的批准或发布凭据，机器人缺凭据不回退个人身份，核环境、gh、credential helper和SSH等常规路径。发布端只暴露限定请求，不做任意URL／shell代理。

业务额度沿用原账本，不复制余额；任务授权、凭据可用、调用成功分开；未知机会不自动返还。角色表现指标绝不自动提升权限、预算或风险上限。

## 13｜合并与恢复

发送前核H/目标/S/r、问题、审核／接收／组合证据、GitHub规则与有效授权；使用服务端支持的head条件，不把本地重读当锁住base。不隐式带入未授权工作。

受理、队列中、实际合入分开。读回真实提交、目标与树；不一致／缺失保留已合入证据待核，暂停依赖该证据的推进，不自动回滚或重复合并。补实际对象验证可恢复，错误目标不能靠补测试追认。迟到回执不倒退最新缓存。

原生merge queue按实际账户／仓库／规则核验，不作为个人仓库前置，不擅自迁移或购套餐。必要用户验证不等合入后才第一次跑；代码合入不是部署。

## 14｜运行、交付与单写

运行状态、审核判断、交付状态、共同用户目标分别保存。开发中→待接收→接收中→待修正／补证据或条件齐备→请求中／未知→已合入；每项有下一步、对象和退出条件。Ready、线程关闭、CI绿不消除未复核阻断。

操作先持久化后请求，不承诺跨SQLite/GitHub严格exactly-once；重试查询原对象。同任务范围、规范化机器／工作区、源分支发布、目标推进分别保护。换会话不能抹去旧责任；核原Run、现场、后台命令和远端后再交接。

读取覆盖不足保持缺口；重启恢复操作、占用、停止和委托状态，不重派。秘书停机不停止普通后台，也不成为唯一撤权入口。

## 15｜消息与产物

Agent自主联系，后台按工作项→角色→准确会话中转，不经秘书逐句改写／审批。同工具复用可靠原生通道，跨工具适配，不重复投递。GitHub不是日常消息总线；正式决定、交付、退回和验收落原Issue/PR再通知；未发布草稿不授权写范围。

送达、暂存、拒绝、未知、回复分开；评论已发不代表会话收到。未知旧消息固定原接收者，不因换负责人偷改目标。原消息与Operation用原回执恢复。

产物登记→匹配版本已读→实际消费验证；路径存在、消息送达不证明行为。新版本重新核对，不可访问私有材料显式标缺口。固定包和GitHub引用够用，不建对象存储或全量聊天镜像。

## 16｜审核、核实和修复

按目标项目有效流程，不新增固定签字层。参考coding-workflow@1772cd2c时，新独立Codex正式审核；有finding时Codex核事实、独立Claude核影响，Codex综合；授权后实际移交写权，在验证会话修复，再独立审新候选。

独立性核作者聊天、自动记忆与隐藏状态，不只换线程名；必要政策保留。最终结果须匹配Run／候选，格式合法不等于语义正确，中间PASS与子代理文字不触发副作用。错误finding用反证，不造空提交。

证据讨论最多三轮；返工只计实际执行并发布批次，超过三次生成既有网页GPT简化反思待办。配额、格式、网络停止有恢复点，不自动换计费。秘书只跟进。用户视角验收按采用的真实场景执行；人不必重复跑已独立证明的全部检查。

## 17｜会话与派发

同工具新会话、另一工具新会话、并入负责人待办。写入同时受本人边界、组织阶段门、当前技术协调、资源／占用和授权约束；调查不自动升级为写入。角色不等于永久进程，工具有效集合是角色、注册能力、授权、原生版本和当前会话条件的交集。

准确session/turn，不用最近会话；创建不证明暂停／恢复／投递可用，错误steer不降级成新轮次。旧长期会话先关联观察，不强迁或夺权，不可见子代理如实标原生内部管理。用固定prompt与可信输入，记录运行器实际版本；独立角色不得拼成一套全能提示。

## 18｜判断后果与整体偏移

复用原PR、运行和验收记录，补最小关联：哪种任务、哪个候选上的什么判断、谁及何种模型／提示／工具版本、后续什么观察、多久／覆盖多少、严重程度、原反例和归因。跟踪放行后漏检、finding被反证、无需升级却交给人的事项；未观察、归因争议、需求变化、后续新代码导致的问题分别保留。

无报告缺陷不算准确；不同风险任务不直接排名；小样本不报精准可信率。独立抽样要包含正常放行成果，不只抽异常；模型评分不能循环自证。统计只辅助人调整委托，不自动扩权，也不默认增加一个分析平台。

一批实际交付后、重复跨任务缺陷时，或人提出请求时，安排新鲜独立审核模式的整体复盘：**上一批已接受目标／规则／能力快照＋累计变化＋当前行为＋当前文档**。不能只比较当前代码与同步改过的文档。区分获准演进、事实文档落后、未采用偏移和累积重复／耦合；缺基线写不足，不认定无漂移。不每PR做全局审计，无变化不固定空转，报告先给技术负责人回应，只有实际取舍给人。

文档三层：人的稳定边界、受委托技术约定、实际事实说明。更新架构／能力文档不自动批准行为变化；也不能把每个文档纠错都变成“修宪”。
