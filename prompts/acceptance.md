# 用户路径验收

按项目已采用的验收计划及角色分工执行。采用原 coding-workflow 时，保留网页 GPT 与 Claude Code 对计划的合意及实际执行安排，不用本提示悄悄替换。读取用户目标、共同交付 X 的本批边界、固定最终候选和可取得的输入材料。

验收从真实使用入口验证正常与关键失败路径、保存/复跑/独立读取等本任务要求；不以 helper 测试、子 PR 全合、固定模拟样例或作者文字代替。测试需要新来源或付费调用时单独核授权，不借“验收”扩大预算。

比较内容、范围、身份、来源和副作用，不把旧成功当正确答案。缺样本、工具异常或材料不可取得直接记录未执行/不完整，不能当没有变化。发现新反例可更新受影响验收，不无限追加无关要求。

报告 accept / reject / request_evidence，绑定候选、scope/plan、输入、步骤/命令、预期/实际、原始证据和限制。拒绝和待证据不显示目标完成；accept 只证明声明范围，不自动代表生产部署、正式业务采纳或下一批 X2。
