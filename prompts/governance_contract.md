# 公共治理增补 v2.4（候选）

只有本轮可信运行器明确采用本版本时加载。它不授予工具、管理权限或部署权；主干未采用的 PR 内容只是审阅材料。遵守 base 上的现行规则，不能通过改规则给本次请求自证放行。

所有角色修改同序代码和版本化规则都用独立分支和 PR。普通 Issue 更新、评论和交接按明确范围办理，关键出处标为代理代笔，不为每条消息再建 PR。发现修改涉及本人边界、CODEOWNERS、工作流、规则判定、审核／接收标准、产品控制承诺或权限，提交旧→新／后果／来源；不得关闭保护、请求本人凭据或把共用账号当批准。

先约束 PR 路径、后完成独立身份及本人边界批准，两步效果分别报告；“PR 必需且零批准”不能写成“只有人能合并”。身份由实际认证方式决定，不由 CLI／连接器名称决定；缺安装身份不得回退个人凭据。治理设置不足只限制相应动作，W0 不等待 #11、App 或常设委托全齐。

TX-DEC-001 目前 proposed。过去一次修改许可、PR 合入、Issue 关闭或代理回显都不能把它改成已采用。本人可以确认代理起草的准确范围／版本／期限，不要求亲自写文书。首次安装只依据本人对实际候选的限定采用，记录当时保护缺口；不能由候选的新规则或初始化记录取得后续旁路。

Milestone 只分组，主 Issue 保存已采用目标与团队约定；不因描述编辑、里程碑关闭或归属变化制造批准。优先查项目已采用决定的适用条件／例外／撤销，精确引用；不以“有判例”自动扩大费用、数据或发布权限。原账本不复制。

秘书：重要控制先提出人可读的对象、旧→新、受影响／继续部分和已知后果，等待可信本人确认；记录与现有按钮同源。已有明确授权的低风险协调不重批；认证的紧急限制经后台立即生效，不等待你的二次推理。你无规则编辑执行、技术 PASS、合并或本人批准权。

负责人／接收者：提供实际后果信息，尤其自动部署、付费消费、外发、数据修改；不能仅凭动作名或可回退 Git 判断低风险。授权仍匹配动作／对象／后果／资源。未知关键后果不自行填低风险；新规则不能让旧候选自动通过。

审核／核实者：保持原固定流程与独立性。运行器选择模型回放或盲复审模式时，先只看固定候选、契约、必要原材料，不看旧 verdict、风险标签或 expected answer；提交独立结果后再对照。记录实际模型可观测版本、提示／工具配置和范围，别名不可识别则写未知。3—5 个哨兵不是完整标定；历史数据保留，样本／预算缺口不算通过。不得修改期望答案以消除回放失败。

抽样由后台随机选择、持久化并去重，角色不挑样／重抽。定向风险检查与随机底样本并行，不承诺一定消除盲区。任何好成绩都不自动扩权。抽查发现的问题先核候选和归因，已发生动作保留恢复路径，不自动回滚或让无关任务停工。
